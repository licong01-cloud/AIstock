# QE callback URL env fix - 2026-05-04

## Scope

- Fixed QE / RD-Agent callback URL construction so WSL and remote QE nodes use the AIstock backend base URL from `.env` instead of stale `infra.compute_nodes.callback_url` or hardcoded defaults.
- Required callback base used for this validation: `AISTOCK_QE_CALLBACK_BASE_URL=http://192.168.50.14:8001`.
- Required FastAPI bind settings used for this validation: `NEXT_APP_HOST=0.0.0.0`, `NEXT_APP_PORT=8001`.
- Compute-node DB rows reconciled for `rdagent-node1` and `wsl2-5080` to `http://192.168.50.14:8001`.

## Root Cause

- `infra.compute_nodes.callback_url` had been seeded with `http://192.168.50.14:8000`.
- The historical dispatch migration generated this value by LAN IP detection with a default `port=8000`.
- The 10-loop HMM validation needed a temporary local proxy on `0.0.0.0:8000` only because the remote node still called the stale DB URL.

## Code Changes

- `backend/services/quantevolver/callback_urls.py`: callback URL helper now reads node-specific and global env bases, validates absolute HTTP(S), rejects localhost for remote nodes, and can fail fast when no env base is configured.
- `backend/routers/quantevolver.py`: single QE submissions require env-backed callback base.
- `backend/services/quantevolver/qe_evolution_service.py`: QE evolution submissions require env-backed callback base.
- `backend/db/migrations/create_dispatch_tables.py`: node seed callback URL now comes from env and fails fast instead of auto-detecting `:8000`.
- `scripts/sync_qe_callback_urls_from_env.py`: one-shot DB reconciliation utility.
- `scripts/_restart_backend.py`: backend restart helper reads bind host and port from `.env`.
- `.env.example`: documents callback and backend bind env keys.

## Business Outcome

- Future QE submissions fail fast if the callback base is not configured through env.
- WSL and remote QE nodes now have the same direct callback base on FastAPI port `8001`.
- A proxy on `8000` is no longer required for loop-completed callbacks.

## Residual Risks

- `.env` is intentionally not committed; each machine must keep its own reachable LAN callback URL in `.env`.
- Existing unrelated dirty workspace files were not staged or modified by this validation.
