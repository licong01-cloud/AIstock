# 因子研发与质量演进蓝图：Codex 主导、AIstock 提供基础能力

日期：2026-09-08；版本：1.0；交付类型：设计文档；实现规划级别：F2。

本次范围仅为蓝图设计、审核与文档合入。以下阶段的代码、数据库、skill、实验及生产操作均未因本次文档合入而完成或获得执行授权。方法论将独立维护，本文不是第二份开发规范。

<a id="1"></a>
## 1. 背景、目标与范围

因子研发的目标是形成用途明确、信息互补、质量可靠且维护成本合理的因子库，而非追求公式数量、自动探索轮次或平台规模。用户选择 Codex 为主要研发工具，Claude Code 可接续；AIstock 负责共享计算、评价、记录和资产管理，不内置一套固定 LLM 研究总控。

目标覆盖四类任务：新因子研发、现有因子改进、衰变与有效性诊断、失效与高冗余因子治理。研究允许得出“不新增”“复用现有因子”“属于模型/标签问题”“当前证据不足”的结论。

研究历史与进度从第一阶段入库，以数据库事实恢复任务，不依赖聊天记忆。因子演进窗口仅实施自己获准认领的能力；需要 QE、QE 数仓或其他业务改动时，向专用窗口提交需求，不跨模块直接修改。

### 1.1 非目标与明确边界

- 不建设新的复杂研究平台、任务调度器、知识图谱、向量数据库、多智能体总控或独立 UI；先复用程序入口。
- 不要求弃用或重写 RD-Agent 全部底层模块；保留有价值的计算组件，研究决策不依赖其固定提示词及模型适配层。
- 不新增数据集导出、冻结、全量哈希、快照、备份、重复数据校验、资源硬限制或未经用户确认的审批/发布门禁。
- 不修改既有数据集、PIT 股票池、交易规则、模型、标签、seed、阈值、实验评价语义或其他模块运行配置来使候选通过。
- 不直接修改其他窗口工作树，不启动/停止其他业务实验，不以研究为由重启服务或抢占其他模块资源。
- 不将研究候选自动设为生产可用，不因低 IC 或高相关自动删除因子、代码、数据或历史实验。
- 计算正确性、无未来信息和真实对照是研究方法要求，不新增机器审批体系；需要新增控制时按现有唯一开发规范先分析、再取得用户批准。

## 2. 架构与现有能力复用

```text
用户：问题、范围、授权
          ↓
Codex / Claude Code：文献、假设、编码、分析、修订
          ↕ 共享方法论 + 客户端轻入口
AIstock：数据读取 / 因子计算 / 评价与相关性 / 研究记录
          ↕
既有数据集、因子库、计算任务与产物
          ↕ 只读契约或专用窗口交付
QE 实验与 QE 数仓
```

研究决策可变，数值计算口径不能随候选表现悄悄变化。客户端更换不改变指标定义，也不要求重跑适用的已完成计算。

### 2.1 已核对的复用入口，不等于已验证全部运行能力

| 现有位置 | 已有职责 | 本蓝图的复用边界 |
|---|---|---|
| `backend/services/quantevolver/factor_official_evaluation_service.py`：`FactorOfficialEvaluationService.compute/get_factor_metrics/get_summary` | 官方独立指标计算与读取 | 复用正式口径，不由研究客户端另写官方指标 |
| `backend/services/quantevolver/correlation_engine.py`：`compute_incremental/compute_pairwise` | 新旧因子相关性 | 优先增量与现有结果；不可计算必须保留原因 |
| `backend/services/rdagent_candidate_service.py`：`cache_task_loops/get_task_loops` | 现有 RD-Agent 假设、实验、反馈记录 | 参考记录模式，不伪造 RD-Agent task 身份容纳所有 Codex 研究 |

| 本地 RD-Agent 的 `rdagent/components/workflow/rd_loop.py` | 假设、编码、运行、反馈分离 | 借鉴步骤与错误反馈，不把其自主循环变成必经路径 |
| 因子库现有 catalog、metrics、monthly IC、classification、correlations | 正式因子及评价资产 | 继续各司其职；研究结论不覆盖正式指标或评级 |

### 2.2 最小共享工具契约

初期优先 CLI/Python 封装，必要时复用已有 API；不同时建设 CLI/HTTP/MCP 三套逻辑。MCP 或 UI 仅在后续出现明确需求时由对应 owner 提供薄封装。

| 能力 | 输入 | 输出与副作用 |
|---|---|---|
| 研究上下文查询 | 问题、候选/基准、用途、时间窗口 | 可用字段、相近公式、可比指标、既有结论；只读 |
| 因子执行 | 候选代码引用、数据引用、股票池、参数、研究任务 | 候选值路径、运行状态与错误；仅写研究产物 |
| 基础评价 | 因子值、评价配置、基准引用 | 共享引擎结果及明确可比范围；正式指标写入只走既有单写源 |
| 研究记录 | 任务、尝试、实际结果引用、结论 | 持久记录 ID 和读回状态；不自动启用因子 |
| 结果对照 | 可比实验/指标引用 | 增量及差异说明；口径不同则说明不可直接归因，不阻断无关研究 |

新命令名、数据库名、字段类型与接口路由在阶段一核实后确定，本文不虚构已存在的接口。优先引用已注册数据版本、产物路径和代码版本，不增加数据内容哈希。

## 3. 独立方法论与 skill

阶段一形成仓库中的独立方法论文档；蓝图维护阶段和职责，方法论维护研究动作，skill 仅作为客户端入口引用二者。不复制两套 Codex/Claude 方法，不把方法全文塞入 AGENTS.md，不绑定个人 profile 或模型名称。方法论版本及适用评价配置记入研究记录，修订不自动重跑所有历史研究。

### 3.1 研究循环

1. **问题与用途**：明确收益排序、条件特征、风险/失效、压缩冗余或使用方式改进；指定可观察时点与作用周期。
2. **知识对照**：查原始论文、最相近公式、已有结果与字段可用性；论文结论不能直接当作本市场实证。
3. **可检验假设**：先写机制、预期方向、最小实现、对照、可能推翻假设的结果；不以字段新鲜度或固定数量评价创新。
4. **有限探索**：文献基准、机制变体与有理由的小范围参数枚举结合；客户端提出并解释，程序计算，不无边界搜索直到出现好结果。
5. **分层评价**：实现正确性 → 指定用途的关系 → 对已有信息的增量 → 实际策略价值。不是每个候选都跑完整 QE；先复用计算和指标。
6. **解释与决策**：区分实现错误、数据不足、当前周期弱、冗余、组合无增量、成本抵消、条件性结果；保存实际尝试并决定继续/改进/结束。

统计周期、股票池、预处理和对照不得为挽救候选暗中改变。需要改评价器时，单独记录问题与版本，重新计算受影响的对照；不得把评价器修复带来的变化归因于因子创新。

### 3.2 时序与研究反馈

- 特征只使用决策时点可获得的数据；横截面和时序操作不得串股票；暖启动与缺失不伪造成有效值。
- h1、h20、更长周期和条件用途分别评价，不设统一 IC 生死线。长周期使用成熟标签，并考虑重叠标签、有效日期数量及不确定性。
- 参与假设修改的窗口属于研发反馈，不继续宣称完全独立测试；已反复查看的近期月份只作诊断。验证划分沿既有契约，不凭固定 purge 天数处理所有周期。
- 使用模型残差寻找信号时，以合适的样本外/交叉拟合预测为依据，不用训练内误差伪造增量。最终策略证据由专用窗口提供。
- 记录失败尝试的紧凑摘要，不只保存最佳结果；经验带股票池、周期、数据和用途条件，不形成永久方向黑名单。
- 使用未来收益标注失败案例只限研发/评价；形成可消费特征时必须回到当时已知信息，不回写未来确认信号。

### 3.3 论文借鉴与不照搬部分

| 原始研究 | 借鉴 | 不照搬 |
|---|---|---|
| [R&D-Agent-Quant](https://arxiv.org/abs/2505.15155) | 假设、开发、实际反馈分离 | 固定提示词和因子/模型同时自主更改 |
| [FactorMiner](https://arxiv.org/abs/2602.14670) | 检索、生成、评价、经验归纳 | 永久禁用方向与论文市场的固定筛选阈值 |
| [AlphaAgent](https://arxiv.org/abs/2502.16789) | 机制/公式一致性、结构去重、复杂度意识 | 用语法不同代替信息增量 |
| [AlphaGen](https://arxiv.org/abs/2306.12964) | 关注因子集合和下游贡献 | 初期建设强化学习搜索器 |
| [AlphaJungle](https://arxiv.org/abs/2505.11122) | 量化反馈引导有限变体 | 初期实现完整 MCTS 平台 |
| [Backtesting Strategies Based on Multiple Signals](https://www.nber.org/papers/w21329) | 关注多次选择与组合过拟合 | 用复杂统计门禁取代清楚的实验设计 |

趋势内回撤与突破承接可作为第一轮案例，但不是硬编码为唯一策略。已有因子复用、信号周期适配、因果路径特征和因子集合压缩均可研究；不要求补全历史分钟线或加入新闻/公告。

## 4. 研究历史与进度入库契约

这是阶段一必交付能力，不可降级为聊天、Markdown 或本地文件唯一权威。研究方法是独立文档；具体任务状态和历史索引以数据库为准。阶段一先核查已有研究记录能力能否无语义污染地复用；不为避免建表而伪装 RD-Agent 任务，也不建立通用事件溯源系统。

### 4.1 最小逻辑模型（不是本次 DDL）

| 记录 | 最少信息 |
|---|---|
| 研究任务 | ID、类型、问题、用途/周期、关联因子、当前阶段和状态、最近完成项、下一步、实际阻碍、负责窗口/工作树引用、更新时间 |
| 研究尝试/结论 | ID、任务 ID、前序尝试、假设、候选/基准版本、方法论版本、数据和评价引用、计算任务/结果引用、关键摘要、错误类别、结论及适用条件、创建时间 |

状态只需表达进行中、暂停、结束及其原因，不设计审批状态机。数据库实现采用现有事务/更新模式避免重复记录和静默覆盖；同一任务的继续操作先读取实际最新记录，有不同窗口并发更新时保留双方事实，不以最后一个聊天总结抹掉已完成结果。

### 4.2 写入与恢复

- 在建立任务、形成一次实际尝试、获得结果、修改方向、交接和结束时写入；不逐工具调用记日志。
- 计算返回任务 ID 后尽早记录关联，长期任务的进行中状态可恢复；窗口断开不等于取消其他模块任务。
- 计算成功但记录写入失败时，报告“计算结果存在、入库未完成”，保留具体产物引用；重试记录时读回去重，不自动重复昂贵计算。不得伪称已入库，也不因此阻断其他业务。
- 支持按状态、研究问题或关联因子查询任务，再按任务 ID 读取目标、最新进度、尝试及结果引用后继续；不能要求用户先从旧聊天找回任务 ID。
- 保存代码版本与稳定产物引用，不只引用即将清理的临时 worktree。正式结果可引用既有存储；不复制原始数据或完整实验目录。
- 不保存完整对话、思考过程、秘密、重复明细或全量因子值。无法确认的历史明确记为未知，只补录可直接核对的事实，不为补齐全部旧历史推迟新任务。
- 无确定分母时使用已完成项/下一步，不生成伪精确进度百分比。历史结论更正保留原结论关系，不静默覆盖过去判断。

## 5. 因子资产质量维护

### 5.1 三种对象分离

研究候选允许失败与变化，不自动进入生产可用目录；研究结论即使没有新增因子也入库；正式因子由既有 catalog 和版本流程管理。研究诊断不能覆盖官方指标、评级或已有业务选择。

### 5.2 衰变、有效性与数据异常

分别判断：预测能力随日历时间下降、作用周期改变、组合贡献下降、交易成本抵消、数据/实现异常。信号随预测期限衰减，不等同于因子随月份失效。

诊断使用同口径历史与近期结果、成熟标签、有效样本量和必要的分状态比较；记录用途，不只用全局“有效/无效”。近期弱不自动判死刑，历史均值高也不免于复核。全 NaN、覆盖改变、股票池差异、无有效配对等首先作为计算/数据问题；相关性不可计算不能补零并宣传独立性。

### 5.3 高相关与失效因子处置

目标是让全库待诊断范围逐步形成明确处置结论，而不是机械删除所有高相关项。优先处理明确错误、完全重复、无增量的高冗余、持续缺乏作用、仍有改进潜力的衰变因子。

比较公式/信息、同周期同股票池表现、稳定性、组合增量、换手与计算成本、现有引用关系。高相关组保留有依据的代表或互补版本；不只按平均相关性或连接链自动成组后删掉全部成员。低相关噪声不奖励，高相关但更稳定/更低成本的替代可研究。

比较前说明信号方向，正负号相反但表达相同信息的版本也属于冗余候选；不得看到近期负 IC 就自动翻转方向。质量摘要引用既有指标的计算批次/日期与口径，不以每次刷新产生新的“最新结论”覆盖旧研究依据。

建议类型为保留、观察、改进、替换、退出默认集合；初期只自动整理候选与证据，不自动实施生产禁用。既有批准阈值保持原语义，任何新增自动淘汰规则或硬阈值先提交成本/风险/替代方案由用户确认。

### 5.4 退出、替换与历史保护

处置顺序：研究判断 → 查询消费者依赖 → 向相关 owner 提交受影响清单 → 在明确授权内改变默认可用范围/替换 → 读回结果。依赖信息缺失时不宣称“无人使用”，不阻断不相关研究。

不直接覆盖旧公式或依赖；前后版本关联并保留旧实验代码和配置引用。共享 `is_available` 若会使现有业务受影响，不能直接切换，须由消费者窗口完成兼容处理；退出默认新选集合不等于让已绑定实验突然失效。

淘汰不是物理删除。历史产物删除、批量清理及数据迁移不在本蓝图实施自动授权中。治理与创新并行安排，不要求固定配额，不以未完成全库清理阻断全部研发。

## 6. 跨模块需求协作与运行隔离

### 6.1 所有权与交付职责

| 需求 | 因子演进窗口可做 | 必须由专用窗口交付 |
|---|---|---|
| 因子研究方法/工具/记录 | 在明确文件范围内设计实现，复用稳定接口 | 与其他 owner 重叠的代码由相应窗口确认处理 |
| QE 训练、标签、选股、退出、回测对照 | 提出因子与实验需求，读取获准结果 | QE 专用窗口修改业务代码与执行获准实验 |
| QE 数仓字段、查询、实验关联和诊断 | 定义所需结果、可比条件和示例 | QE 数仓专用窗口设计接口/迁移与验证 |
| 因子官方评价/评级/共享 catalog | 复用、提出明确补齐需求 | 若属于其他窗口活跃或登记所有权，则由 owner 实施；不绕过单写源 |
| HMM、Selection、Paper、Advisory | 给出因子版本、用途、变更影响和交接需求 | 各业务窗口接入、验证、决定激活 |

工作树隔离不等于数据库、计算资源或业务身份隔离。任务开发前以 changed files → ownership → registry → test plans 确定允许范围；任何未获认领的共享文件不得以“只有少量修改”为由直接编辑。

### 6.2 需求交接模板

一项需求只保留：需求 ID/关联研究、业务问题、现有能力缺口、所需输入输出及示例、周期/股票池/版本/可比条件、读写与性能影响、负责窗口、验收方式、优先级、交付引用和当前状态。

需求关联与当前交接状态记入研究数据库，详细实现状态引用 owner 的既有 Issue/PR，不另建跨窗口项目管理系统，也不依赖聊天记录证明对方已交付。

提出需求不等于已获实施/DDL/实验授权。owner 用现有 feature/BUG 流程执行，因子窗口验收其公开结果；不复制第二套业务实现。接口未交付时，只明确相关策略评价尚未验证，使用现有数据开展可独立完成的研究，不扩大全任务阻断。

### 6.3 不影响其他模块正常运行

- 初期默认只读消费业务数据，候选代码/产物使用任务范围；不改变现有默认配置、数据路径、PIT、scheduler 或业务指针。
- 使用现有计算执行能力，按需读取并复用结果，优先增量，不启动全库/全量实验替代小任务；不新增系统资源硬门禁。
- 在可能共享数据库/计算节点时说明成本，使用已有可控执行方式，不控制其他窗口进程。无法证明并行无影响时不承诺“零影响”，先与 owner 安排隔离资源或执行时段。
- 未来接口采用兼容新增，旧调用仍可用。需要改变旧行为时由业务 owner 提交迁移方案，不能在因子窗口暗中切换。
- 不将全仓实验、所有业务回归或等待全部 PR 合入作为例行前置；只验证真实依赖和当前修改范围。

## 7. 分阶段实施方案

只有三个交付阶段；每阶段可以由新窗口凭数据库记录继续，不拆成大量互锁小阶段。本次仅交付蓝图，不创建未来研发任务、数据库表或自动任务。

| 阶段 | 实施内容 | 完成证据与退出条件 | 专用窗口依赖 |
|---|---|---|---|
| P1 方法与记录闭环 | 独立方法论、skill 薄入口、最小研究记录入库/读回/恢复、现有工具衔接；一个新研究案例和一个旧因子诊断案例 | DEV 数据库验证；获准生产迁移后读回；新会话由数据库恢复；结果关联可查；错误不伪装成功；无业务回归。没有发现 alpha 仍可完成方法验证 | 仅实际复用入口有缺口时提需求；不等待完整 QE 新诊断 |
| P2 因子库质量维护 | 可比指标概览、衰变/异常/冗余建议、改进替换关系、依赖查询、分批存量处置 | 诊断可解释；生产动作有精确授权和读回；被引用旧版本仍可用；全库范围有已处理/待处理清单，无未知被假装清除 | catalog/评级/消费者变更按 owner 交付，不跨界 |
| P3 QE 反馈与持续演进 | 按需接入可比实验和趋势诊断，关联组合增量，复用现有更新触发与增量计算 | 对照能解释模型/配置差异；无结果时明确不可归因；方法演进记录可追溯；其他模块默认行为不变 | QE、QE 数仓需求单独交付；不接管训练源码 |

阶段状态分为“源码/DEV 验证完成”与“获准生产应用并读回”；生产授权尚未取得时，明确报告后者未执行，不把前者伪称已上线，也不为此阻断可独立的文档/代码工作。P1 的入库与恢复能力必须实际验证，不能以文件代替数据库宣布功能完成。

每轮研究结束于：已计划尝试有结果或明确失败原因、记录已读回、结论/下一步明确；不能为了凑成功而无限迭代。用户可指定研究轮数或时间安排，不把预算建议转化为全平台硬门禁。

全库治理是持续任务，不承诺某一日期彻底消灭所有衰变或高相关因子。衡量有效处置率、重复研究减少、计算/修复成本与组合增量，而不是因子数或记录数。

## 8. 验证方案、发布与回滚

### 8.1 实施阶段的最小测试

- 研究记录：重复提交不重复入库；并发更新不静默丢失结果；计算成功/数据库失败的恢复不重算；更正能追溯；新会话恢复下一步。
- 查询/交接：按状态或因子发现任务，不依赖聊天中保留 ID；跨窗口需求可查 owner 交付引用；只读查询不得暗中触发数据同步、缓存入库或新实验。
- 计算：与共享评价程序一致；时序/股票隔离正确；数据异常与无效信号分别报告；匹配条件才计算可归因增量。
- 治理：弱但样本不足不自动淘汰；高相关有用途差异不机械删除；无有效配对不填零；替换不破坏已有版本引用。
- 接口与运行：任务产物隔离，旧接口/默认配置保持；跨模块测试由 owner 执行并交接实际结果，不以 mock 代替生产功能验收。
- 数据库：既有 DEV 上执行相应 migration/DML、重试/回滚或向前修复验证；生产需精确目标授权再执行读回。不得创建新测试库或要求备份导出。

### 8.2 本次文档验证与合入标准

本次 changed files 仅本文，归属 `docs.architecture`，使用 docs-fast-new。进行两轮以上实质内容审核、问题修订、UTF-8/相对链接检查、`git diff --check`；额外复用 `python scripts/aistock_feature_workflow.py validate --design docs/architecture/factor_research_evolution_blueprint_20260908.md --tier F2` 检查蓝图结构。结构校验通过不代表阶段实现完成。

PR 只消费最终 HEAD 的必要 CI，按已有规则合入，不额外运行无关模型训练、全库因子计算或全业务测试。不增加新 CI job、审批规则或重复人工授权。

### 8.3 发布/回滚

蓝图合入不激活功能。后续按阶段提交源码、DEV 验证、精确生产授权、迁移和读回，分别报告。默认新工具不改变旧业务；若研究工具出错，暂停其自身新请求并保留记录，由 owner 修复，不停止其他服务。回退客户端入口/应用代码须保留研究历史；数据库回滚不得删除已产生的研究记录，选择兼容向前修复或经授权的精确方案，不套用破坏性 down migration。

## 9. 风险与未决事项

| 风险/待核实项 | 处理原则 |
|---|---|
| 历史记录表是否可复用、实际字段类型与索引 | P1 精确核实后定 schema，不把 RD-Agent 专用缓存冒充通用研究权威 |

这些实施事项不阻碍本次完整蓝图交付，但不得把尚未实现的能力声称已上线。
