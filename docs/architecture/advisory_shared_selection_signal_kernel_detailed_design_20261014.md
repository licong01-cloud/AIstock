## 1. 目标、继承关系与非目标

目标不是让两个系统读取同一份评分，而是让它们分别执行同一份完整的基础选股实现。新增已交付 StrategyPackage 通过元数据和冻结资产进入同一入口，不为每个包编写专用程序、复制算法或要求重新进行 QE 实验。

本设计继承[荐股蓝图](advisory_strategy_conditioned_model_blueprint_v1_20260710.md)、[实盘单日与历史批量同核设计](advisory_live_daily_historical_batch_shared_kernel_f2_detailed_design_20260816.md)的同语义原则。后者包含的 Advisory projector、名单/episode transition 仍为荐股私有；不是把整个 Advisory 业务内核交给模拟盘。旧 H0 的44日 golden、历史实验、证据固化和自然采集不恢复为本次前置任务。

2026-10-13性能补充设计位于既有优化分支：`feature/advisory-batch-inference-performance-20261013@c6eb3d65f4a308e875dc336776dfd001f8bce67a`，文件为 `docs/architecture/advisory_batch_incremental_inference_performance_detailed_design_20261013.md`。它是本设计的优化参考，不把该分支或旧收据当成本次源码合入、模拟盘接入或运行态完成证明。其“跨包/跨日复用”在本设计中限定在同一个消费者拥有的任务/session 内；不扩展为跨荐股与模拟盘共享评分、特征结果或任务状态。

不在本次范围：新的因子/模型训练、QE 演进或实验准入、价格预测模型研发、分钟线执行算法、资金仓位/订单算法、数据库迁移、数据补齐/激活、服务重启、UI、通用缓存或调度平台。

### 2.1 已有组件，不另建两套选股算法

共享代码已经存在一部分；完整数据/特征批量、公共批量 provider 与两侧产物适配并未据此全部完成。共享服务中现有可选 Advisory Phase1 trace 捕获不得成为公共计算的必需业务依赖；若需解耦，由所属 owner 保留兼容入口并改为消费者可选观察者，不新建留档平台。

### 2.2 两个真实包仅作为代表样本

优化分支已有 LSTM 包 `pkg_cc7eccb6202e4816b9d7c7d6b748bd37`（20 Alpha158＋26动态因子）及 TCN 包 `pkg_8dbd396d27184de6aa5fe288011220f6`（20 Alpha158＋24动态因子）的只读验证。二者现有训练序列为20步，不能把20、46或44写成通用内核常量。Alpha158 优化覆盖这20项公式；其他原入口支持的特征保持原公式执行，不因不命中优化路径而拒绝策略包。

两包有20个共同 Alpha158 名称及18个共同动态因子名称；名称相同不足以证明代码、参数、输入、横截面人口及初始化语义可复用。模拟盘反馈的“两个模型共享57因子闭包、约40秒/日”不适用于本次两个包，不能作为性能承诺。

现有参考：最终 LSTM 两日内核380.16/419.32秒，TCN首日含启动403.48秒；各4907只评分。TCN探针旧/新全评分和输入身份 EXACT_PASS；LSTM最终探针自身 equivalence 为 PENDING，另与既存 r3 reference 完整比较通过，不能混称探针自行完成双臂验证。位置：`X:/AIstock_temp/advisory-perf-20261013/lstm-final-2day/`、`tcn-final-firstday/`。这是短窗口算法/性能参考，不是 LocalSIM 接入、半年吞吐、收益确认或实盘激活证据。

### 2.3 模拟盘指出的三个接入点

1. Alpha158：采用混合特征通用路径，不使用“全动态因子限定”替代原模型特征。
2. 历史序列：按冻结处理器和各包实际序列长度构造 LSTM/TCN 输入，不重训、不重新拟合。
3. LocalSIM：逐日完整评分转换为原生 signal artifact，并接入真实身份、审计、幂等与断点恢复。批量 CLI 当前保留已完成日期并明确失败，但拒绝覆盖旧输出；这不等于 LocalSIM 自动恢复已完成。

前两项有优化底座，不等于任意新包已完成消费验证；第三项由模拟盘专用窗口及相关公共 owner 实施，本窗口不得代改。

## 3. 共享边界与唯一实现

```text
               唯一公共库代码（不集中计算、不发布业务结果）
        股票池 → 数据 → 特征 → processor/序列 → 推理/融合
                         → HMM/risk/tradability → 基础排序/TopK
                    ↑ 调用                    ↑ 调用
             荐股私有运行 A              模拟盘私有运行 S
             task/session/cache A        task/session/cache S
                    ↓                         ↓
             A自己的评分及名单           S自己的评分及账户产物
             价格/收益等附加模型           仓位/订单/成交/账户
```

图中公共层是一份库代码，不是同时为两个系统计算一次的中心服务。两个调用分别执行，不发送、查询或引用对方的计算结果。

公共层沿用现有组件，增加必要的入口组合和批量执行能力，而不是重写 `selection_computation`、建立新选股平台或并存两套权威算法。单日是日期计划长度为1的同核调用；历史批量与日频仅在输入准备、资源复用和执行拓扑上有差别。

| 共享计算范围 | 明确保留的私有职责 |
|---|---|
| 已交付包/资产解析、股票池解析、只读数据准备 | Program/account/release/binding 的选择及生命周期 |
| Alpha158、动态及混合特征、冻结 processor、序列采样 | 荐股二级模型重排、收益概率、买卖价格区间、独立弃权/退出建议 |
| 模型执行、多腿/seed组合及既有权重算法 | 模拟盘目标仓位、资金、订单、成交、费用和 NAV |
| 原生 HMM、risk/tradability 基础过滤、稳定排序/TopK | 荐股名单/episode、模拟盘持仓和交易状态转换 |
| 统一信号值对象及审计字段生成规则 | 调度、结果保存、任务 checkpoint、事务和运行态发布 |

共享 HMM/risk/tradability 只执行显式注入的原政策，不把荐股学习型 Admission、价格模型或现金建议自动施加到模拟盘。政策不同允许输出不同；同一包、日期、人口、数据与政策下，两侧应产生相同基础信号。

公共计算的providers必须只读注入，不创建带隐式训练/写入的业务服务。现有 `selection_center/hmm_runtime.py` 在provider未注入时会构造 `HMMTrainingService`，系数路径可调用 `generate_daily_coefficients`；新共享计算接入只能消费合法已交付HMM snapshot/系数，不能借此启动训练、补系数、写DB或控制scheduler。原政策禁用HMM时保持disabled；启用且必需来源缺失时按原合同明确 unavailable/UNKNOWN，不填系数1、不把训练当作fallback。本窗口不修改HMM源码。

## 4. 策略包通用合同

### 4.1 不绑定包 ID，绑定可执行语义

`package_id` 只用于查找和记录身份，不用于选择专用算法、包白名单、专属阈值或专属数据窗口。禁止 `if package_id == ...` 的运行分支。代表包 ID 可出现在事实表及测试输入，不得进入生产算法判断。

| 差异项 | 权威来源及运行要求 |
|---|---|
| 模型类型、代码与权重 | manifest/冻结资产及既有执行接口；不按包名称猜测模型族 |
| 因子及依赖闭包 | 冻结 factor code、依赖声明及 feature schema；不假设两个包有完全相同因子集 |
| 特征顺序/维数/dtype | 训练 schema 与冻结 infer processor；不得删除 Alpha158、按字母重排或补零冒充特征 |
| 序列长度与采样 | 冻结 dataset/processor 及原模型执行语义；非序列模型也通过同一入口 |
| 股票池及成分日期 | 已交付包/universe 合同和既有只读解析器；保留单指数、多指数并集及全市场已有规则 |
| 排序方向/TopK | 原包语义与调用政策；当前公共计算支持1～50，Top10/20/50参数化，不暗改现有上限 |
| 多腿、seed和混合权重 | 原生组合及权重合同；冻结权重或原生滚动权重保持原适用范围，不自创新融合公式 |

新增已交付包应零包专用代码接入，不重新要求收益评估、QE 训练、人工审核或强制历史回放。模型/资产/输入字段读取是必要的执行描述，不是新增包准入门禁。缺少实际执行必需文件或 schema 不一致时报告具体不可执行原因，不伪造成功或改变包内容。

### 4.2 新模型与新特征的扩展

已支持执行合同下改变包、因子数量、Alpha158比例、股票池或序列长度，不改变两侧算法。全新的模型接口、特征输入 schema 或包合同版本若超出现有执行能力，由对应 owner 扩展一次公共适配器；两个消费者不分别开发同一种模型执行器。

通用性不等于提前实现一切未知未来模型，也不等于把既有优化仅限制于两个样本包。慢速但正确的原公式是明确的执行模式；不支持的真实新接口则是明确的能力缺口，不回退为别的模型或特征。

## 5. 入口、时钟与结果合同

以下名称是拟定逻辑合同，不宣称源码类或公共 API 已存在。实现优先扩展原 `prepare_from_live_inference_dates`、signal preparation、`InferenceEngine` 和 selection computation；不新建同职能平台。

### 5.1 `SelectionSignalRequestV1`

| 字段组 | 必需内容 |
|---|---|
| 运行信封 | `consumer_scope=ADVISORY/LOCALSIM`、task/run身份、私有输出根和资源预算；不改变评分数学 |
| 包/政策 | 有序包身份及 manifest、原生组合模式、每包 runtime profile/TopK、政策版本；完整声明 raw-affecting 配置 |
| 日期计划 | 有序唯一的逐项 `{decision_date, data_cutoff, target_trade_date}`；不排序去重来掩盖原计划错误、不删日期 |
| 数据 | `DB_HISTORICAL`日频、节点根、已交付数据/revision/schema/单位/复权身份及逐日实际成员 |
| 资源 | 当前消费者自己创建的 session、明确日期块/内存与临时路径；不可借用另一消费者 session |

数据截止 `C`、评分/决策日 `D`、目标交易日 `T` 分开保存。按现有业务映射约束，进入模型的任何记录不得晚于其合法 `C`；`T` 可为尚未发生的下一交易日，但不能读取未来 T 行情。两侧对外旧 `trade_date` 字段的含义由适配器显式映射，不能只按输出文件名比较。

适配器同时映射 `trade_date_requested`、`effective_trade_date/score_trade_date`、reference-price日期及各stage的as-of时钟，保持旧字段含义，不将 `T` 当作HMM/risk输入的默认截止。只要求各stage消费其原合同允许、在本次决策时已可得的信息；执行日的成交可用性检查仍属模拟盘私有执行，不倒灌进更早评分。调用与实际记录日期不一致时返回具体合同错误，不改日期或从最新配置补填。

BUG-1912 明确各能力并非统一绑定 C：[provider 时钟合同](../contracts/strategy_package_selection_provider_clocks_v1.md)
规定模型/参考价/risk/PIT 行业截止 C，停牌 eligibility 按冻结政策在 D 观测。
停牌是原生基础选股约束，不仅是下单时的检查；仍由唯一 TradabilityFilter 过滤递补。
HMM 保留原生 C/D 标签与生效日，验证行情/训练信息不超过 C、资产可用日期不超过 D，不能将 D 标签改取 C 行或生成系数。

历史计划必须逐项提供截止映射，不能把最后一天 cutoff 广播到整个历史区间。固定 cutoff 的原合法请求仍保留其明确语义，不能冒称每日增量。TopK 不参与模型资源选择；改变10/20/50只重算必要后处理，不重复模型推理。

### 5.2 `SelectionSignalDayResultV1`

共同值对象包含：逐日完整 raw score及每腿可用性、有效候选、原排序/tie-break、TopK、排除或未知原因、逐日成员/资产/输入/政策身份、原阶段审计和错误状态。结果由本次调用生成，不能将另一系统产物装入对象冒充本次计算。

- raw score 保留完整实际评分集合，不只保存最终 TopK。score/rank方向、并列处理、缺失语义沿用原实现。
- 同时保存请求/实际人口、`universe_count`、`score_count`及未评分原键的可用性诊断，区分合法未评分与漏产物；原来源没有具体原因时保持UNKNOWN，不编造停牌或缺数据结论。完整评分指原合法可评分集合完整，不承诺为未满足原模型输入的股票伪造分数。
- 完整运行且原政策确实产生零候选，使用既有 `VALID_NO_CANDIDATE`；模型错误、全特征不可用或输入未完成不能包装为空成功。
- 正常停牌/缺 bar 按原模型采样、字段 UNKNOWN 和原政策处理，不因优化统一删日期、删候选或阻断整个包。是否可买由原 tradability/消费者交易政策判断，不擅自修改。
- 统一结构不包含账户现金、真实目标仓位、订单或成交；现有候选等权字段如需兼容，由对应原政策投影，不能声称是实盘资金仓位。
- HMM/risk各 stage 同时保留原值与有效结果，不用 stage 名称一致掩盖配置或人口差异。

### 5.3 失败合同与旧接口兼容

公共计算沿用现有typed异常与candidate outcome，不另造一套业务成功标准。返回或错误信封至少包含 `failed_stage`、原 `reason_code`、请求/有效日期、输入身份、完整/部分状态和已完成日期引用；`retryable`只在原组件有明确依据时提供，不把错误一律自动重试。

完整运行的零候选是成功状态下的 `candidate_outcome=VALID_NO_CANDIDATE`，不是模型/数据失败。批次只有全部计划日完整才COMPLETE；中途失败按消费者既有终态表达，不能把前几日成功概括为整批成功。老单日返回类型、错误类和正式发布语义由对应owner的兼容适配保留；新字段使用明确版本，不静默改变旧 `trade_date` 或强迫旧调用新建研究任务。

## 6. 完整计算与性能设计

### 6.1 数据及因子

每个消费者自己的任务按输入身份准备一次未复权原始分区，再构造每个日期合法的历史视图。只读引用已有大资产或验证过的链接，不按包/日期复制同一大型数据文件；必要不同 schema 各生成一次。若节点不能引用原资产，明确报告路径/能力缺口，不默认复制到C盘。

缓存 raw 未复权输入不等于复用区间末日前复权视图：复权因子、availability、修订、历史起点及池成员均参与日视图身份。横截面归一化、行业分组或排名按当日实际人口计算，不把多个池合在一起归一化，也不跨日期使用未来统计量。

Alpha158和有限窗口时序特征复用有序因果计算；未知动态代码只拿合法当日视图，不能访问含未来行的底层批量 buffer。同一消费者内部的不同包，仅对代码/参数/输入/人口/缺失/初始化完全等价的交集复用特征，剩余各算一次，随后分别选择冻结 feature order。

EWM/expanding 与移动 warm-up 起点不能直接全区间算一次再切片。已有 `m_tech_atr_ratio_14d` 的 EWM 是反例；保持原初始化或证明精确等价，不截短近似、不修改已批准因子来换速度。

### 6.2 冻结处理器、序列及推理

同任务/session按资源身份加载冻结模型模板与 infer processor，逐次隔离可变状态，不执行 fit、训练或标签统计。不同包/腿/seed的处理器及模型状态不混用，即使特征名称相同。原 fitted列序、dtype、缺失处理、sample索引及 `(sample, step, feature)` 或原模型指定布局均保持。

模板不能安全克隆或processor子集不能独立复用时，明确以原正确的fresh-load执行，记录未命中及成本，不拒绝本来可执行的包，不把共享可变网络状态当作优化。公共入口保持节点Python/模型运行环境兼容；计算helper不得通过import启动荐股业务容器、数据库服务或加载价格模型。

序列只使用合法截止历史。原采样中的 `ffill+bfill` 只在合法历史窗口内按训练语义执行，不借用 cutoff 后样本。日频追加与历史批量同一采样算法；冷启动、缺历史及新入池场景显式保留原语义。

单/多 Alpha、seed和组合共用同一分派路径。滚动 IC 权重如原合同允许，只使用当时已成熟标签，不把未来持有期收益用于当日权重；此类原生能力由 StrategyPackage owner 实施，本窗口不修改 QE 或权重算法。

先减少读取和重复因子计算，再评估 forward batch/线程；已有 forward 不足1秒，不能把约200秒数据组装及约120秒动态因子问题包装成 GPU 模型瓶颈。不同维数/序列/处理器的模型可以共享满足身份的输入，不强行拼成一个张量。

### 6.3 基础政策、排名及增量

HMM、risk、tradability 和包融合各调用原实现，使用显式政策及合法日期，不由消费者复制算法。冻结完整评分后计算各自需要的TopK。消费者后续模型重排是独立模块，不回写公共 raw score。

日频增量是原始分区/特征/session 的执行优化，不是重训模型权重。新增数据、迟到修订、复权变化和池变化触发精确受影响范围重算；有限窗口只传播其合法依赖，递归特征传播到所需历史，不能统一只更新最后一天。更改原始输入身份必须失效相关缓存，对照原单日完整重算验证。

数据服务当前没有的增量或 revision 公共能力只作为最小接口需求交给其 owner；已有只读路径先完成荐股范围工作，不等待全平台验收，也不绕过 identity/PIT。

## 7. 运行隔离、缓存与资源

共享的是代码、信号 schema 和生成规则，不是计算完成的对象。正式调用不得读取另一消费者的 raw score、特征结果、SelectionRun、名单、订单、收益、task checkpoint 或结果索引。测试可显式比较两侧独立输出，但该比较不是生产取数路径。

| 资源 | 隔离规则 |
|---|---|
| 基础数据/冻结包资产 | 两侧可只读访问同一权威源；不重复复制。操作系统页缓存不算业务结果共享 |
| 模型/processor、输入及特征缓存 | 各自session/namespace/预算；同消费者内合法复用，无跨消费者单例或共享可变 buffer |
| 评分与候选产物 | 地址包含消费者、run和日期；不跨消费者发现、命中或回写 |
| 状态、失败、恢复和取消 | 各自owner处理；一侧失败不改变另一侧状态或触发其重启/终止 |

缓存键使用稳定内容身份，包含合法截止、输入 revision/schema/单位/复权、实际池、代码/参数/初始化、feature order、processor、模型和raw-affecting配置；涉及可变执行数值的层级同时绑定dtype/device及实际运行库/代码身份。执行记录另保存消费者/run；相同逻辑身份也不允许跨消费者命中。缓存 miss 是正常重算，不是策略包门禁；损坏或身份冲突不能伪装为命中或空成功。

历史运行使用有界日期块，复用重叠窗口，不按每个日期保留完整历史 DataFrame。预算覆盖保留缓存、工作缓冲、模型调用副本和 GPU，不拿模板缓存512MiB当总体RSS上限。默认先单worker，测量后决定本任务内部并发；不控制另一窗口任务，不以“QE必须空闲”替代实际资源评估。

临时文件及本任务新建缓存只能使用 `X:/AIstock_temp/<consumer>/<run>/`；WSL为 `/mnt/x/AIstock_temp/<consumer>/<run>/`。已有正式数据/模型保持其原只读路径。检查节点X盘挂载和解析位置，不能回退C盘、WSL默认 `/tmp` 或复制完整输入。任务结束只回收自己的可再生临时对象，不删除正式或另一任务产物。

## 8. 逐日产物、发布与断点恢复

### 8.1 计算事实与运行信封分开

`semantic_identity`绑定包/模型/输入/政策/合法日；`storage_identity`绑定消费者/run/day/阶段。两侧同输入可以有相同语义摘要，但其运行证据、观测时间、产物引用和发布状态是各自真实生成的。

BUG-1912 起，共享结果与 risk/selection receipt 显式保存 `selection_provider_clocks_v1`
及实际 provider 调用日期；禁用能力以无 lookup 日期表达，不冒称读过数据。
语义身份包含这些证据和完整原生 receipt hash；storage identity 也绑定语义身份。
旧 C 过滤结果不可当作 D eligibility 结果命中或续跑，已存产物不可覆盖；身份验证的原始评分可在本侧明确重算后处理。

当前公共 repository 的查询及唯一键包含 package/manifest/date/source/runtime hash，未体现消费者隔离；不能直接把全局 artifact 命中当成本次独立计算。新共享计算入口必须绕开跨消费者结果发现，产物通过现有消费者私有 task/artifact存储及相应原生writer发布。不能把 consumer/run 混进评分政策 hash 来假装原算法改变，也不能伪造原生 receipt 或捕获时间。

公共原生产物若无法在现有存储合同中表达独立来源，记录该适配缺口并由所属 owner 解决；不能静默共用全局评分行、覆盖旧记录或以本地JSON冒充原生发布完成。本次文档不执行或预授权 schema/DDL 变更。

### 8.2 LocalSIM适配由专用窗口实现

模拟盘适配器调用公共计算代码生成自己的完整评分，按现有 `SelectionScoreArtifact`/`DailySelectionEvidence` 合同映射目标日、cutoff、package/manifest/runtime release、数据/profile、完整人口和真实stage/source字段，再进入原 target/执行链路。参考价若是账户消费必需字段，由现有只读价格合同按合法日期独立补入，不能使用荐股价格预测代替它。

不得调用另一个系统的已完成评分，不得修改冻结模型、不截取TopK后补造全池hash，不得把未获证明的历史数据身份升级为原生完整证据。原 LocalSIM account/release/policy 和 broker 语义保持，订单与持仓变更不进入公共计算。

### 8.3 原子发布、幂等与恢复

1. 对每个消费者/run，准备日期计划和同源输入，raw评分可以合法预计算。
2. 单日完整结果先写本任务临时对象，校验完成后原子发布；文件发布在同卷/同存储原子边界内完成，DB发布沿用原writer事务，不能声称X至F的跨盘rename是原子操作。索引只引用已完成日，部分成功不能标记整批 COMPLETE。
3. 名单/episode或账户状态从第一个未完成业务日顺序推进；后续已算评分不代表对应业务已提交。
4. 失败保留已完成日与具体阶段，恢复只查本消费者本run或明确登记的自身重试关系；按既有交易日志防止重复提交和重复记账。若产物已发布但索引/checkpoint尚未推进，先核对本侧真实提交记录后推进；不删除产物重做交易，也不以文件存在代替业务已提交。
5. 重新执行允许复用自己的已验证输入/结果；代码、资产、输入或政策变化不能冒充 exact retry，更不能跨消费者恢复。

本次设计不新增统一事务管理器。公共计算无数据库写事务；消费者沿用自己的提交/checkpoint机制，模拟盘跨日提交和 crash recovery 必须由其专用窗口证明。

### 10.2 等价比较

固定同包/manifest/资产、合法C/D/T、实际池和数据revision、政策、运行环境，对照原正确单日、新单日、新批量及增量；比较完整symbol/date键、raw分数、每腿及有效rank/tie-break、TopK、stage原因、缺失/空候选和逐日输入身份。消费者run ID、路径、时间是运行信封，单独核对真实来源，不要求两次运行伪造相同时间。

股票集合、排序、状态、政策及日期必须一致。浮点采用原环境下可实现的精确对照；必要容差在执行前按dtype/算法声明并报告最大差异，不结果后放宽，也不允许容差掩盖TopK变化。比较两个系统时保证基础政策相同；政策不同的结果不据此判公共算法不一致。

### 10.3 性能及资源

同条件串行对照，记录冷准备/热续日、完整wall time、各阶段、股票-日期吞吐、实际读取/写入字节与次数、因子执行及模型/processor加载、cache命中/失效、峰值RSS/GPU和后台负载。未测SELECT次数保持未知，不以日志阶段数冒充查询频率。

逐步扩大到覆盖块边界的连续窗口，检查续日和总内存趋势；半年/全年耗时需真实长窗口测量，不能线性估算冒充完成。40秒不是冻结SLA；原股票池、特征、模型、政策、PIT和身份不降级。最终要求同条件实际吞吐改善与结构去重同时成立；只有局部加速或延长timeout不等于端到端性能完成。

两侧独立运行仍各自支付必要计算成本；不把共享代码宣传成跨系统只计算一次，也不以选股耗时代表完整模拟盘订单/账本回放耗时。
