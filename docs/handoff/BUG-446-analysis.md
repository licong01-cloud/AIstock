# BUG-446 analysis and fix plan\n\n## Conclusion\n\n- Current SimulationLifecycleScheduler._post_close_terminalize_miniqmt_run() reads only submit-time open_order_evidence and submit_result_gate from run.run_payload_json before deciding the post-close terminal status.\n- _miniqmt_post_close_terminal_status() directly maps stale open_order_count > 0 to FAILED_TERMINAL, without calling _sync_miniqmt_snapshot() or _reconcile_after_submit() at EOD.\n- Therefore an order that was open at submit but filled later intraday can still be marked FAILED_TERMINAL after close, contradicting the MiniQMT unified design: section 4.1 maps vn.py OMS/ledger as the durable source of order truth, and section 6.2 forbids misusing success states or letting reconcile success erase submit failure.\n\n## Code checks\n\n- CodeGraph query for _post_close_terminalize_miniqmt_run returned no caller rows in the local graph; current source shows the caller is _terminalize_post_close_miniqmt_runs(), reached only from run_once() and post_close_reconcile_once() post-close flows.\n- Existing _reconcile_after_submit() already performs _sync_miniqmt_snapshot(), recomputes ledger open-order evidence, side-effect evidence, and submit_result_gate. Reusing this path at EOD preserves the submit_result_gate invariant while avoiding a new reconciliation implementation.\n\n## Fix plan\n\n- In _post_close_terminalize_miniqmt_run(), force a fresh broker/ledger reconcile before terminal status calculation by loading binding/runtime context and calling _reconcile_after_submit().\n- Decide terminal status from the refreshed run payload written by that fresh reconcile, not from the stale input payload.\n- Persist terminalization audit with fresh_reconcile: source, as_of_time, sync/reconcile payload keys, sync evidence, fresh open-order evidence, and fresh submit_result_gate. Keep old evidence only as previous_* audit fields and never use it as a fallback decision source.\n- If fresh broker reconcile fails, raise DataUnavailableError with reason_code=MINIQMT_POST_CLOSE_FRESH_RECONCILE_FAILED, run/binding/strategy/trade_date identifiers, and the original error type/message/context. Do not fall back to stale payload.\n- Keep _reconcile_after_submit() and submit_result_gate semantics unchanged so reconcile success does not weaken submit failure protection.\n\n## Acceptance mapping\n\n- Added regression coverage: open at submit, broker fresh snapshot shows filled before close, EOD terminalization is not FAILED_TERMINAL and exactly one post-close broker snapshot cycle occurs before the decision.\n- Added regression coverage: fresh broker query failure loud-fails and leaves the run INTRADAY_RUNNING without writing miniqmt_post_close_terminalization.\n- Required verification: targeted pytest, changed-file ruff, diff check, l0, validation_module_registry_l0, and paper_v2_l3.\n
