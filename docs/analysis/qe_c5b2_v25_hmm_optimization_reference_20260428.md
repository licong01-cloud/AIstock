## 1. 核心结论

- Loop1/Loop2 都使用了更新后的 V25 执行策略逻辑；workspace 文件和权威文件仅换行符不同，归一化 hash 一致。
- V25 的 `<100` 股尾仓修复在本实验中没有复现旧问题：Loop1/Loop2 全周期和最终均没有 `<100` 股持仓，也没有 `<100` 股卖单残留。
- Loop2 不存在全周期资金使用率明显偏低的问题：平均现金比例 4.42%，低于 Loop1 的 4.61%；中位现金比例 3.61%，也低于 Loop1 的 3.94%。
- Loop2 存在“最终日现金比例偏高”的现象：最终现金 2,005.46 万，占净值 11.66%，最终持仓 45 只；这是终点快照问题，不是全周期资金闲置问题。
- Loop2 收益下降的主因不是模型训练、因子、label 或 V25 执行，而是 HMM snapshot 从旧 baseline 切到新 covfix w5 zscore 后，HMM 调整后的 Top50 排序和真实持仓路径发生变化。
- 新 HMM 的 `trending` 状态在 3D/5D/10D/20D 验证收益为负，但当前策略真实持仓中位数约 4 天、P90 超过 40 天；继续用 `preset_A` 对 `trending` 加权 1.05，与真实持仓周期不匹配。

```text
+----------------------+-----------------------------+-----------------------------+
| 指标                 | Loop1旧HMM                  | Loop2新HMM                  |
+----------------------+-----------------------------+-----------------------------+
| snapshot             | 252fdd35...                 | 4c9b5f7...                  |
| config               | baseline original w3 raw    | covfix w5 zscore candidate  |
| train区间            | 2022-01-01 ~ 2024-06-30     | 2023-01-30 ~ 2026-01-23     |
```

因此，新 HMM 的 `preset_A` 继续把 `trending` 乘以 1.05，会把组合推向不适合真实持仓周期的行业状态。

## 11. 后续 HMM 优化建议

1. HMM 系数不要只按状态名固定为 `trending=1.05 / neutral=1.0 / fading=0.96`。必须先按 snapshot 的验证结果重新校准各状态在 1D/3D/5D/10D/20D 的 forward return。
2. HMM preset 应该与真实持仓周期绑定，而不是只与训练 label horizon 绑定。当前策略真实中位持仓约 4 天，P90 超过 40 天，因此至少要看 3D、5D、10D 的状态收益。
3. 对新 covfix w5 zscore HMM，当前证据不支持继续在多日持仓策略中给 `trending` 加权 1.05；可测试 horizon-aware preset，例如对 5D/10D 为负的 `trending` 降权或中性化。
4. 每次 HMM 优化必须输出以下诊断：HMM Top50 与 raw Top50 重合度、HMM-only 股票 forward label、state 分布、持仓贡献、月度收益差异、资金使用率、买入未成交率、最终持仓数。
5. HMM 回测要使用 PIT/rolling 快照，避免用训练截止日晚于回测早期日期的 snapshot 进行整段历史回测，防止未来信息污染对比。
6. HMM 优化验收不能只看 IC/RankIC。Loop1/Loop2 原始 IC 完全一致，但组合收益差异很大；必须以完整回测收益、回撤、换手、持仓路径和资金使用率共同判断。
