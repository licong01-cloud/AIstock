# 因子研究方法论

版本 2.6（2026-10-09）；依据：[因子演进蓝图](../architecture/factor_research_evolution_blueprint_20260908.md)与[研究比较能力集中增补设计](../architecture/factor_research_comparison_supplement_20260909.md)。本文是研究方法唯一正文，不取代项目开发标准，也不授予生产写入、实验启动或进程控制权限。C-1～C-7 是方法引用编号，不是新增 workflow/生产门禁。

本次将假设先行与 AIstock 独立经验检索落实为方法增补，不修改 Skill 或业务代码，不运行因子计算。P1/P2 的记录、执行、恢复和质量查询能力继续保留；比较能力及 2.1 完整评价要求见集中增补设计及后续实际回执。指定文件检索与问题包已有交付，不等于数据库跨记录检索或研究增益已实现。填写 method_version=2.6 不代表已完成全量评价或新能力已交付。已有研究保留原方法版本和证据；对受影响候选另建关联尝试/更正，不自动重算全部历史。后续实现、研究及其登记与本文修订分开报告。

## 目的

Codex/Claude Code 提出假设、编写受审查代码、解释对照；AIstock 提供已有数据、确定性指标工具和研究记录。以有用途、有增量、可维护的因子库为目标，不以新因子数量为目标。已有因子的诊断、改进和有依据的退出建议同样是研究成果。

当前研发主线优先发现有价值的新因子或新表示。存量诊断、维护及用途改进单独报告，回答已声明问题后结束，不能因更容易完成而连续替代新机制研究。新公式不等于新来源信息，已有输入的新表示只要在指定用途有可信增量，也可成为候选；不将“必须使用全新数据源”设为目标。

## 每轮研究

1. 先用 `scripts/factor_research.py list/show/context` 查相关研究及已有因子，避免重复试错。研究入口应看到表达式、实际输入依赖、相近基准及失败结论；接口未补齐时明确所缺项，不猜测全库已去重。历史事实来自数据库记录，不根据聊天印象推测；可按[§2.5](#rdagent-assistance)读取 RD-Agent 相关经验，不把全库检索或节点可达设为前置。
2. 先写可证伪的预测现象及竞争解释，再写候选公式。研究卡记录问题、研究角色、用途/持有期、假设族、机制或文献依据、方向及来源、数据字段/单位/可用时间、基准 B、候选 F、替换/消融版本、削弱假设的结果、探索/拟合/评价区间、方法版本。研究单元是“一个问题、一组基准、一个候选增量、一个时间外比较”。
3. 以文献最简复现、已有失败定位、低换手/覆盖改进组织少量候选，不让模型凑公式数量。小样本只用于公式、单位、因果时间、覆盖原因和结构近邻的技术预检；通过技术预检的候选必须进入下节规定的完整独立指标和相关性评价，不能因小样本 IC 弱、高相关或局部增量不显著而跳过。不存在固定淘汰率、饱和 cell 禁入、名额、IC 生死线或承诺的运行秒数。
4. 审核候选实现后运行本任务子进程；已有产物优先复用。任务与尝试登记后才能开始新计算；数据库提交失败保存结果，用 attach 补登记，不重跑。
5. 分层解读：实现正确 → 全目标 PIT 股票池/全有效历史的独立指标与相关性（近期优先）→ 指定用途的关系及 B 与 B+F/替换版本的时间外差值 → 获准的实际策略验证。独立指标与增量不能互相替代，研究对照不冒充 QE 收益、成交能力或生产晋升。相关性未计算不能宣称全库去重；无有效样本不能填零。
6. 登记条件性结论、未解决问题与下一步。完整评价有结果或真实失败、数据库读回、下一步明确后可结束；没有发现 alpha 也可完成一轮。仅技术预检完成、计算中断或能力缺失时，只能结束该项操作并说明完整评价未完成，不能将其记成因子整体无效或评价已交付。

研究卡可以是 tasks.context_json，尝试/反馈/结论保存在 records。新窗口通过状态、因子名、问题关键词发现任务，读取当前快照和最近记录。普通研究轮次复用已批准方法、数据库记录和 repo 外产物，不要求逐轮另写设计或创建文档 PR；候选代码仍须审查，代码/schema/生产变更继续走既有开发流程。方法改版不自动改写过去结论。

## 研究角色、证据与信息增量

research_role 与 task_type 正交，前者写入 context_json，不改变既有 new_factor/diagnosis/improvement/redundancy 枚举。

| 研究角色 | 首要比较 | 不作为统一否决条件 |
|---|---|---|
| 新增预测信息 | B 与 B+F 的时间外预测/排序差值；基准有合理的拟合机会 | 低原始 IC 或低偏 RankIC，可能存在事先声明的交互 |
| 替换改进 | 原版与替代版在可比风险/参与度下的效果、换手、覆盖和计算成本差 | 残差信息接近零，可能是更便宜或更稳定的同类信息 |
| 状态/风险/条件变量 | 预先指定的交互或预测/决策损失差；同时看参与程度与漏掉的成功机会 | 自身无条件横截面 IC，不能靠不交易制造成功 |

依赖覆盖矩阵使用已确认输入与显式 unknown；历史审计的数量、标签和优先级是带时点的线索，不代表当前目录。字段 Jaccard、窗口族、机制只用于近邻检索，不证明语义等价。同源不等于重复，空白数据源也不保证 alpha。元数据分批修正需相应写库授权，不是研究的硬前置。

<a id="c-1"></a>
### C-1：张成度与来源

拟合期 R²_span 表明候选方差被指定基准线性解释的程度，属样本依赖诊断，不证明剩余信息无价值。F=X+0.01S 即使主要方差来自 X，剩余 S 仍可能有预测价值。样本内 R²=1 须披露有效样本、设计矩阵秩和残差变异；仅据有限样本拟合不能认定构造重复，无法识别时记 spanning_undetermined，不填成确定结论。

仅当候选按已核实构造是明确列出的、同一决策时点可获得的基准输入的确定函数时，方可判定无新增来源信息。该变换不得引入未声明外部数据、额外历史或未来拟合参数。F=X 是完全重复，F=g(X) 是已知变换；同一数据源不足以认定重复。不能把来源信息关系当作使用价值判决。

<a id="c-2"></a>
### C-2：变换与统计定义

同日、同有效样本，x=rank(F)，y=rank(前瞻收益)，Z 含截距、预先声明的连续控制项排名和行业哑变量；不把行业代码作为有序数值。分别用同一 Z 回归 x、y，得到 e_x、e_y。

- 原始 RankIC = Corr_P(x,y)。
- 偏 RankIC = Corr_P(e_x,e_y)，两侧残差化后不重新排名；它是事后关联诊断，不是可交易表现，也不是信息增量的必要/充分条件。
- Corr_P(e_x,y) 是半偏秩相关，不等于中性化信号的 RankIC；第一版不实现半偏量。若另行研究残差信号，其 RankIC 为 Corr_P(rank(e_x),y)，按实际用途单独评价。

对照原始与偏 RankIC 使用共同样本，同时保留原始样本覆盖与丢失原因。收益残差化只用于评价，不得把该回归结果用于生成当日信号。零残差或无有效变异时统计量无定义，报告原因，不输出 0、不放大数值噪声。

已知严格递增 g 保持排序，严格递减 g 反转排序；当相应基准排名已进入 Z 时，候选排名残差为零。水平口径中 g 可改善表示，重复列也可改变正则化效果，不能强求所有 B+F 的差值为零或把改善一律叫重加权。结论按构造和实际使用方式分别说明。

<a id="c-3"></a>
### C-3：基准与相似性

基准 B 至少考虑该用途下显而易见的现有做法；明确来源集合、公式/依赖/拟合期相关性检索和去重规则，不固定近邻数量，不为候选挑弱对照。无存量近邻、无简单基准、无可比业务方法分开披露；可只对已声明基准得结论，不声称相对全库。

B 与 B+F 同目标、窗口、样本权重和参数选择规则，分别拟合，只用已成熟标签。等权组合可测指定使用方式，但加入重复列就能改变权重，不能独自证明新增信息。交互须事先声明，不在线性失败后换模型直到得到正结果而沿用原结论。实际选模型/控制集的自由度记入研究历史。

替换比较明确为 B 与 B−被替换项+F，叠加比较明确为 B 与 B+F。独立指标、配对预测和成本分析须分别标明其实际信号/权重路径；不同实验不能拼成同一用途的肯定或否定结论。评价器/报告口径有错，先限定受影响结论并修复所需对照，不据此否定整个因子族，也不重跑无关研究。

合成信号比较称“相似性诊断”，高整体相关不能证明同一性，低相关也不证明有用。评价期可计算预先声明的相关性或用途对应的交易分位重叠，但不能反过来挑有利规则。替换用途可选择更相关的重叠量而不强制叠加指标。

<a id="c-4"></a>
### C-4：验收与证据强度

已知构造用例验证数学和程序行为；真实市场候选允许不支持或证据不足，不要求三个案例必须产出三个预设答案。构造测试包含完全重复、已知单调变换、强张成但残差有用、纯噪声、条件交互、合法低换手替代。随机统计样本用合理误差范围，不承诺每次都显著。

2.0 的少量否定/边界复核保留为历史方法观察，不能估出总体假阴性率。2.1 对技术有效候选均完成完整评价，不只挑少量初筛弱候选复核；记录技术预检与完整评价差异、实际耗时及适用边界，全样本历史结果也非绝对真值。“没有诊断本来会怎样做”只使用运行前原方案。实测、事前计划、估算与未知分开，不把估算节省冒充实测。工具正确和案例完成不等于方法提高发现率，更不等于 alpha 已成立。

<a id="c-5"></a>
### C-5：两条结论轴

信息关系：完全重复（构造）／已知变换（构造）／主要可解释（统计）／尚未解释（统计，相对声明控制集）；证据不足时原因另列，不强行归类。使用价值：在指定方法中改善／未见改善／证据不足。两轴独立：无新增来源信息仍可改善使用；不同信息可能无用；高度相关可有用途增量；残差存在可被成本抵消。

结论统一限定为“在本次声明的基准集合、使用方式和评价区间下，观察到何种增量”。评级、来源可用位、低相关、高有效秩、流程完成度均非价值证据；不引入自动晋升或退出阈值。

<a id="full-evaluation"></a>
## 完整独立评价与近期优先

这是用户批准的研究交付范围，不是新 CI、运行时准入、评级淘汰或人工审批。小样本可以发现技术缺陷并进入修复，不能代替有效候选的完整评价；技术不成立或数据不具备只能给技术/可行性结论，不能伪装为 alpha 否定。

- 股票：使用研究开始时声明的完整目标历史 PIT 股票池及适用规则，不是当前存活股或预先挑选的几百只股票。通用价量覆盖全部历史适用股（含当时合资格的退市股）；两融/指数专用因子按当时资格/成分定义，不能因观察到缺失或表现弱再收缩范围。保留每股全部有效区间；原始理论分母、数据可得、因子有效及配对样本分开，不把读取器漏股排除后重算分母。
- 日期：覆盖完整可用历史至当前所选数据集实际截止；当前目标为 2018-08 起至 2026-08-31，以实际起点、暖启动、数据缺失及 C-7 标签成熟分别解释。以后跟随数据集最新日期，不永久钉住本次日期。输出请求/实际信号区间、数据截止及每个期限的成熟末日，不用字段名 full 冒充全数据集覆盖。
- 重点：2024 年首个交易日至最新可评价日期优先展示；同时列全期、2024/2025/2026 各年（当年注明截至日期）、最近 6/3/1 个月及月度序列。后续新增年度自然延伸，不去掉全历史背景。近期窗口以数据集截止和该期限成熟边界解释，不把旧样本末端的 recent 当当前近期；不能用全期平均遮蔽近期失效，也不能把近期表现外推为未来保证。
- 指标：复用因子库权威计算口径，按各窗口列 IC/RankIC、ICIR/正向比例与有效日期数，h1/h5/h10/h20 表现，分组收益/单调性、多头与超额收益/夏普/回撤、覆盖与换手。每项标明方向、期限、预处理、基准、毛/净及实际样本；当前引擎未提供的期限×窗口格列缺项和后续工作，不用 h1 组合夏普评价 h20 策略，不把排序换手代理当资金换手。成本后指标按既有权重路径条件提供；没有路径不伪造净收益。状态变量独立指标仍如实展示，但不能仅按无条件 IC 否决其角色价值。
- 相关：计算本批候选之间及候选对全部存量可评价因子的成对相关，覆盖全有效历史与上述重点窗口；采用有声明的同日横截面/聚合口径，注明方向、有效股票/日期及缺失。相似性不是收益相关；已有不同窗口或 EWMA 结果不能冒充全期同口径结果。候选×存量计算不要求重算未受影响的存量×存量。缺少值或不可比的因子单独列明，既不填零，也不宣称全库已去重。全范围相关可用于诊断；若用其选择基准，所用评价历史记作 research_feedback，不冒充独立基准选择。
- 对照：与存量独立指标比较须股票范围、日期、期限、方向和评价版本可比；旧批次不满足则补算对应对照或明确不可比。先报告完整独立结果，再结合角色匹配增量决定改进/复用/继续/结束，不以一个统计量作自动晋升或淘汰。

数据集实际版本也属于对照口径：指标截止日相同、查询时间最新或相关性刚刷新，不证明独立指标已使用同一数据修订版。复用可比结果，仅补本研究需要的旧版本对照；局部参考集相关或仅全期 EWMA 结果不冒充全库、多窗口评价。近期优先不等于只选表现最好的月份；同时展示成熟标签数与覆盖，极少成熟日期的高数值不作为稳定增强证据。

计算复用同口径候选值及共享价格/PIT/标签上下文；仅补缺失股票、日期、指标和因子对，不重新导出数据集、冻结、算全量哈希或重算无关存量。批处理须保留逐日全目标截面排名与最终聚合语义，不能平均小股票批次的 IC/相关代替全截面指标。实际执行时间、完成/缺失项如实记录，不承诺未实测时限。

## 抽样、增量与成本

- 选股依据历史 PIT 与当时可用信息，不筛“今天仍上市且历史完整”。样本覆盖与问题有关的规模/流动性/行业或事件；时间优先连续，暖启动保留。廉价样本用于辨别问题，不承诺固定算力比例或淘汰率。
- 初筛为明确技术问题、可进入完整评价、样本不足三类预检判断，不是发布状态机，也不能替代完整评价。样本不足时记录原因并在完整目标范围评价；数据/执行能力不足则列待办。完整评价后仍不确定可以结束，不反复偷看至显著即停。
- 排序用途按日期、共同股票样本计算 delta_t=RankIC_t(B+F)-RankIC_t(B)，报告均值及其不确定性；替换/状态用途用预先声明的成本、覆盖或损失差，不统一成 delta IC。日期是统计观测单位，不把股票×日期作为独立观测。
- HAC 说明带宽选择、有效日期、缺口及适用假设；标签重叠只是相关来源之一，不统一固定 lag。不同连续窗口不拼接成连续序列，样本不足则不提供不受支持的显著性。配对处理协方差但不承诺检验力一定提高。
- 成本先定义持有与权重路径、单/双边换手和买卖费率，再按实际权重变化扣费；h20 标签不等于每日全仓换仓或重叠持仓组合。15/30/60bp 仅可作明确标注的压力情景，不是已测成交成本。无路径不报告组合净收益，有路径可报告盈亏平衡交易成本 bp，不从 IC/换手推导唯一盈亏平衡 IC，不声称真实成交或容量。
- 相邻目标权重之差未计持仓价格漂移时只标记交易量代理；不能称实际资金换手。未来收益缺失后的剔除/重新归一化不得冒充可执行持仓收益；按既有持仓、停牌与估值合同处理，能力不足明确保留未验证。组合净值/回撤须包含初始资金基点。修正仅复用既有能力，不在研究窗口重建 QE 执行引擎。
- 工程执行次数、假设/参数/方向选择、已查看评价范围分开；重试不是新假设，一次 attempt 可含多次选择。第一版报告统计量、试验范围与“无多重性保证”；不以 BY/FDR 名称掩盖无效 p 值或适应性选择。

## 评价与因果时间

- 候选特征不得读取未来价格/未来成员关系；截断前缀与跨股票边界测试用于检查实现，不是每次导出追加的全量数据验收。
- 标明数据截止日、暖启动、信号评价期和成熟标签范围。共享引擎 h1 是 T+1 到 T+2，h20 是 T+1 到 T+21，不另造收益公式。
- 已参与提示词改写、候选选择或参数选择的窗口标记 `research_feedback`。数据库字段名 out_sample 不自动等于未触碰的独立样本外；不能反复看结果后仍宣传独立验证。
- 保留数据缺失、计算失败、标签未成熟、信号弱和不可比较的差别。评价器已有报告保留，未知原因写未知，不编造停牌或补零。
- 因子方向与机制事先明确。查看结果后变更方向或公式属于新尝试，不覆盖旧结果。
- LLM 共识不是有效性证据。跨模型或跨数据版本的策略差异无法直接归因于因子；需 QE owner 提供可比对照。

<a id="c-6"></a>
### C-6：控制集与评价接触

控制集与基准的选择依据、调整过程及区间必须记录。允许在声明的探索/拟合区间修改控制集；进入最终评价前确定选择规则。依据评价结果修改后，该区间转为 research_feedback，不再声称独立验证；对这条研究选择链，该接触事实不可通过重新切分同一历史抹除。

区分历史重新评价、历史时间外测试（拟合时间隔离但研究者可能接触过）、真实前瞻评价（登记后形成且标签成熟）。不能从已查看的整体历史中切出“干净窗口”；历史评价仍可用于诊断，不要求等到未来才能研究。declared 方向来自事先声明，fitted 方向只能在拟合期估计并记录锁定时点；不改写旧方向，也不修改官方评级引擎的历史语义。

<a id="c-7"></a>
### C-7：标签成熟

拟合样本的标签实际可获得时点不得晚于拟合截止时点。复用现有 `HOLDING_PERIODS` 与交易日历查所需价格日期，不对期限名做算术。当前 1d/5d/10d/20d 对应 shift_n=2/6/11/21，收益为 Close(T+shift_n)/Close(T+1)-1；因此当前 h 日持有标签在 T+h+1 价格可获得后成熟。若截止日收盘数据已可用，最后信号日至少回退 h+1 个交易日；盘前截止不得使用当日收盘。

实现验证入场/出场所需价格日期与可获得时点均已到达，并区分价格缺失和标签未成熟。成熟筛选使用完整交易日历，不按删除缺行后的股票序列移位；不改变既有收益公式。训练/评价边界按实际标签区间排除跨界样本，不对所有任务套固定 purge/embargo 天数。月度空值只有原始结果/owner 可确认原因，不把全部 8 月 h20 空值自动归因于尾部未成熟。

## 方法演进与首轮研究

先复现文献基础现象，再定位失效条件并研究最小改进；机制叙事、覆盖空白、LLM 共识不是实证。先看失败历史具体被哪个基准解释、哪个期限不成立、是否集中小盘低流动性、成本是否抵消，以及何种新证据才值得重试。财务 PIT、两融时点或 QE 失败反馈缺口转成有 owner 的需求，既不编造代理也不永久回避；公告/新闻及历史分钟线扩建不在本次范围。

原首轮问题（既有 intraday_divergence 中长期复核、近重复替换、一项两融机制）及其历史结论保留。2.1 起对技术有效、尚未完成且仍在本次研究范围的候选完成完整评价，先呈现 2024 年至最新日期结果，同时完成全历史，不靠新增公式掩盖未完成项；不因此重启已完整评价且无新依据的旧规格。旧版本或不可比的 h20 结果只作调查线索；同版本、因果且口径可比的历史回放可用于价值判断，不要求未来行情确认。两融数据前提未满足可停在可行性结论。真实结论允许不支持或不确定，不能以工具测试通过宣称发现概率上升。

研究方向随结果调整，方法/工具因误判、统计错误或低效集中修订，蓝图架构仅在反复出现真实能力缺口时调整。每次版本变更记录原因、范围、适用研究和必要对照；保留原结论，不因改版重算全部历史。完整研究周期、正式 QE 对照与生产处置分别授权。

### 2.2 用途驱动的方向调整

- 具体公式、交互或使用方式不被支持，只约束该次已检验假设；不推导整个数据源、期限或方向永久无效。允许基于结果提出有机制依据的新尝试，沿 C-6 如实标记历史接触与选择，不靠无限变体寻找显著性，也不要求等未来行情才能验证。
- 板块轮动分别研究行业选择与行业内选股；趋势跟踪分别研究延续、回撤承接与失效。股票型候选仍完成完整 PIT 独立评价及相关性，行业排序/条件用途的评价为补充，不替代它。纯行业变量按完整目标行业面板评价并声明实际历史；复制到多只股票不增加独立行业观测，不能用“股票数×日期”夸大证据。
- 行业配置不先剥离目标行业暴露再以低残差 IC 否决；行业内选股可以按声明用途控制行业。优先复用已有广度、扩散、相对强弱、参与差、协同性及压缩信号，不把换窗口或改名当空白方向；是否新增取决于机制和实际缺口。
- 优先现有批准数据修订版，不因新方向重建数据集。新外部数据先核实接口、历史、单位、发布时间与适用对象；接口存在不等于当前权限或历史完整。数据接入/补录交数据 owner，不用今天的成员关系回填历史、不将发布前数据用于特征。
- 已完整评价且低价值的候选仅保留现有任务/结论的紧凑记录及必要引用，不另立证据固化、全量重算或归档工程；不据此删除已引用产物。近期改善与不同信息来源是选题线索，同源新表示也可研究；实际投入顺序由下述蓝图当前章节维护，不设数量配额。

方向线索保留在[蓝图 §19](../architecture/factor_research_evolution_blueprint_20260908.md#discovery-priority-20261008)，本次工作安排见[§21](../architecture/factor_research_evolution_blueprint_20260908.md#hypothesis-memory)；历史排期不是实时任务状态，先查数据库已有结论，不自动续跑。本文不复制执行排期，不新增自动淘汰、资源限制或审批。

<a id="direction-and-decay"></a>
### 2.3 现有数据内的选题与退化诊断

选题先看存量表达式、可比结果及已有失败结论，再提出可证伪的投资问题。公开论文、指数表现或制度变化须注明市场、区间、股票范围与交易口径，只作为机制线索；不能据此判定本库某因子已经退化或必然有效。低相关、少用字段和最近一个月高 IC 都不是独立的选题理由。沿用现有研究记录，不建新平台、评分或入口门禁。

因子变弱至少区分以下原因，按问题选择必要比较，不要求每轮追加全部计算：

- 日历时间上的预测关系变化：同时看全历史、分年和近期，固定可比方向与口径，报告有效日期及不确定性，不能只展示改善月份。
- 风格与样本变化：解释市值、行业、波动、流动性暴露和覆盖变化；共同样本比较同时保留完整分母结果。行业配置问题不能先剥离行业作用再据此否决。
- 期限变化：分别看 h1/h5/h10/h20，形成窗口与未来持有期分开。短期反转弱不证明中期趋势失效，h20 好也不能掩盖其他期限弱。
- 使用与成本变化：区分排序信号、组合权重及真实可执行路径；比较风险、参与度与换手，不把少交易造成的低成本当新增信息。
- 数据或实现问题：核对实际修订版、单位、复权、可得时点、PIT 分母和标签成熟，只修受影响结果，不把实现错误叫经济衰变，也不为方法改版重算全库。

近期表现用于确定优先调查对象，不保证未来持续。若据近期结果选择候选、方向、基准或状态，该历史属于 research_feedback；采用历史滚动拟合并遵守标签成熟合同仍有研究价值，无须等待未来行情。市场状态只能由信号时点已可得信息定义，不能用事后牛熊标签生成特征。

本轮范围是现有已发布数据：估值/股息字段不等于财务公告 PIT 或未来分红质量；订单大小不等于机构身份；日频数据不等于盘口/真实持仓；股票行业分类不等于指数成员历史。行业内比较需使用实际可得的历史分类，价格与筹码成本需核对复权口径。字段或历史不足时只限制相关假设，不以代理数据冒充、不在因子窗口补录、导出或激活数据集。

已经完整评价且未支持的具体候选，只保留最小结果，不追加证据归档、无新依据重算或连续更换窗口挽救。停止的是已检验规格，不是永久封禁同源机制；重新研究须说明新机制、输入实质变化或已确认评价错误。技术预检尚未完成或仅小样本弱，仍不能称其整体无价值。优先找用途增量，不凑数量；研究角色、完整评价和 C-1～C-7 保持不变。

### 2.4 从预测现象到可交付候选

本节调整研究决策顺序，不新增工具、状态机、公式配额或计算门禁。C-1～C-7、三种研究角色及完整评价范围保持不变。

1. **选题前明确可观察差别。** 写出同等简单暴露下，哪一种当时可知的行为差别可能对应不同的后续表现，以及什么结果会削弱它。例如研究资金流与价格的先后关系，应与资金流均值、自相关、同期价格动量分别比较，不能用“机构吸筹”等无法从订单档位识别的叙事代替证据。公开论文只提供问题或最简对照，其他市场的结论不直接移植为A股事实。
2. **查明公式结构再投入评价。** 从现有表达式、输入依赖和相关历史中寻找简单近邻、已失败规格及同一构造；未覆盖的目录范围明确列出。已知完全重复可以复用等价的既有结果并结束该重复问题；高相关、近似重复或小样本弱本身不免除技术有效候选的完整评价。若发现问题已被同口径结果回答，引用结果，不再创建新名称或重新计算。
3. **现象分析与公式评价共享计算。** 可先用完整目标范围的描述性关系判断接下来值得问什么；它没有产生一个完整候选时，只能报告现象线索，不能判定尚未定义的因子整体无效。一旦形成技术有效的候选，仍完成全目标历史PIT、全有效历史四周期独立指标与存量相关性；直接复用该次输出做现象分解，避免先做一轮筛选、再重算同样的矩阵。探索结果用于调整公式、方向或控制集时按C-6登记选择过程，不称独立验证。
4. **增量比较尊重用途。** 用明显简单方法及经过核对的近邻作对照，B/B+F拟合机会一致。高相关、同源或某个年份/期限为负均不自动否决；不要求每年、每个周期同时为正。根据事先说明的用途，综合幅度、近期与跨年表现、有效样本、反例及不确定性，判断继续、保留线索或结束。条件用途必须同时报告参与机会和不利情形；不能事后只保留成功分组。已经完整评价且不支持的具体规格不追加无新依据的变体。
5. **适时交接业务验证。** 研究层有可复核用途线索时，可将公式/版本、比较规则、完整独立评价、增量结果及剩余执行问题打包给QE owner；不要求研究窗口先证明生产策略收益，也不因QE尚未运行宣称因子无价值。QE接收、执行、策略证据与正式因子入库分别记录，因子入库仍由用户批准。其他研究继续进行，不因批量QE排队停工，不在本窗口重建执行引擎。

研究记录沿用现有context_json与records，用紧凑文字区分三种成果：新因子/新表示候选；存量用途改进；数据/代码修复。一次任务可有多种成果，但同一结果不重复计数。已有生产目录项、完成独立指标、可以交QE和已验证生产用途是不同交付事实；不得靠改称“用途研究”将新因子零产出掩盖，也不把工程修复叫新alpha。

复盘只回答：哪些不同假设得到检验、哪些被既有信息解释、哪些有可交付增量、实际计算和修复投入多少、下一问题为何不同。新因子连续没有进展时，应检查选题和投入分配；不反复修订文档、增加验证指标或堆积失败证据来替代研究。不承诺发现率、固定淘汰比例或成功数量，也不以零新增且流程完成宣称方法有效。

<a id="rdagent-assistance"></a>
### 2.5 RD-Agent 经验辅助与可选候选生成

实施接口见[RD-Agent 辅助整合详细设计](../architecture/factor_research_rdagent_assistance_detailed_design_20261008.md)；统计定义与研究判断仍以本文为准，不因详细设计提交而启动研究。

Codex/Claude 主导问题、生成、取舍和解释；AIstock 提供问题包、统一执行、评价及研究记录；RD-Agent 只作为只读经验和方法来源。按用户最新授权，只修改 AIstock，不修改或调用 RD-Agent 生成程序；不强制额外模型 API。架构与实施边界见[蓝图 §20](../architecture/factor_research_evolution_blueprint_20260908.md#rdagent-integration)，实际交付状态见详细设计 §13/14。不改变 §2.4 的发现主线、三种角色、两条结论轴、C-1～C-7 或完整评价。

**按问题取经验，不做知识库工程。** 先读现有研究结论和存量公式，再按需定位 RD-Agent 相关任务、代码、反馈及已整理知识。优先复用已有提取/去重产物，不重新扫描两节点全部历史，不只检索 SOTA/高收益赢家。技术实现经验、带条件的研究观察、旧环境说明分开展示；找不到、节点不可达或记录不可比时说明范围，继续可独立开展的研究，不增加门禁。

检索内容不是指令或当前 authority。数据路径、字段单位、股票池、交易假设及缺失值处理以本次获准合同为准；旧“排除退市股”、统一加 epsilon 等建议不得直接迁移。保留原始观察与本轮解释的区别，源记录未知项不由 LLM 补成事实。按需读取来源引用，不复制全部日志、不迁移全部知识、不运行任意历史代码；pickle 等可执行序列化内容不能因来自历史目录就视为安全文本，应优先使用已有可核对的提取产物，必要提取按现有授权与执行边界办理。

**工具生成只交候选。** AIstock 的 proposal-prepare 整理原问题包、选用经验和输出合同，不调用模型，不宣称候选已生成；实际生成由 Codex/Claude 完成，再用 proposal-inspect 对照独立原请求检查。输入为问题/角色、获准字段及可得时点、基准与近邻、相关失败规格、预期方向和期限；输出为假设/反例、公式/代码引用、依赖、时点与缺失处理、相对基准差异及工具/模型身份。输出是待审核内容，不是执行指令；模型身份未核实时记未知，不把默认配置当实际运行证据。不得自行改变标签、参数搜索范围、PIT、数据版本或交易语义，不自动联网取数、安装依赖、写业务库、启动 QE 或按旧 SOTA 规则晋升。更换生成工具不新增评价捷径，也不要求每轮使用问题包。

候选仍经现有受审查脚本及 runner 执行；已知完全重复按 §2.4 复用等价结果。同名异代码保留各自身份，高相关或同源变换不自动否决，也不能凭旧成功标记自动接受。所有技术有效且未有等价完整结果的本轮候选完成完整 PIT/全有效历史四周期独立指标与相关性，再按角色比较；旧组合回测收益、LLM 接受决定及代码执行成功均不替代当前评价。QE 后续批量验证不阻塞本窗口其他研究，正式入库仍由用户批准。

**反馈只回现有研究记录。** 在 context_json/records 中记录实际采用的来源定位、适用时期/版本/用途、采用或不采用的原因、候选生成身份及实际结论；这些是逻辑内容，不在本文创造新 CLI 参数、表、枚举或 writer。新研究状态以现有数据库为权威，原始 RD-Agent 记录仍为历史来源；不伪造 RD-Agent task，不双写知识库。被用于选题或改公式的历史按 C-6 记录为 research_feedback，不通过检索包装恢复独立性。已完整评价且不支持的规格只保留紧凑结论及引用，不追加证据固化、无依据重算或归档任务。

**检验辅助价值而非工具声望。** 有必要单独评价工具效果时，在相同问题、数据和模型条件下比较有/无相关历史经验；再考虑可比预算下的直接研发与生成支路，或单独研究模型升级。它不是每轮前置，不为此重跑失败历史。不能同时改变模型、数据、框架后声称某一项有效。工具对照使用分别组织的上下文，披露是否接触另一侧候选/结果及原有共同历史，不把同一会话先后运行当独立对照，也不为此新增 agent 总控。记录实际候选差异、技术修复成本、完整评价及用途增量、耗时和可得的模型成本；未知成本不估成实测。重复使用已接触历史时如实标注，少量案例不证明总体发现率。强模型可能改善假设与实现，不保证 alpha；没有增益可停止生成支路、保留有用检索，不以生成数量或 SOTA 次数验收。不承诺成功率、不要求等未来行情、不新增固定预算门禁。

### 2.6 假设先行与可检索的独立研究经验

**先问题，后表达。** 先从相关历史和现有数据提出金融假设，说明可能的行为/摩擦、价格为何可能尚未充分反映、作用期限/对象、最强竞争解释，以及什么可观察差别能区分解释。事实、历史观察、文献观点和推测分开。允许从机制未知的经验现象或表示改进出发，明确未知即可；不能为了满足模板虚构经济机制，更不要求先证明因果关系才研究。

**公式是代理，不是解释。** 用现有字段构造最简可检验表达，说明每个窗口、比值、乘积或条件的用途，同时给出明显简单基准和结构近邻。复杂表达可以有用途，但不以复杂度、新字段或低相关证明创新；不强制跨源、因子数量或逐轮增加数学操作。订单大小不证明参与者身份、日线不证明盘中路径、估值比不证明未持有的财务事实。数据不能识别假设时报告可行性限制，不写成因子价值已被否定。

**反方审阅服务研究，而非另立门禁。** 实现前检查假设/代理是否匹配，是否只是在重述反转、动量、规模或流动性；结果后区分技术错误、已有信息解释、不支持、条件价值和证据不足。不用提示词关键词、LLM 共识或评分决定准入，不强制第二模型或新的人工审批。所有技术有效且无等价完整结果的本轮候选仍按完整评价节执行；这些动作不成为小样本淘汰的捷径。已回答且无新依据的问题只引用旧结果，不补证据工程。

**历史只存一处，经验可独立检索。** AIstock 现有两表是本模块研究历史权威；context_json 保留当前研究问题，records 的现有 payload 保存紧凑结果/经验与更正。摘要仅解释原结果，不覆盖数值或正式指标；未来索引若存在也是可重建副本，不是第二历史系统。第一版先补问题/记录/机制/字段的查询，不建设向量库、知识图谱、后台调度或 UI。

每条经验只需能回答：原问题与规格是什么、实际观察是什么、在哪个数据/股票范围/期限及用途下成立、限制与竞争解释是什么、什么新依据才值得继续，并定位原记录。字段未知保持未知；不为满足模板追溯补齐全部旧研究。失败也可被检索，但失败规格不升级成永久方向黑名单；相似来源不自动认定重复，检索分数不是经济价值。

RD-Agent 有价值内容按问题选择性引入，最小保留来源定位、选定片段、原观察和本轮解释；通过现有记录入口进入获准的 AIstock 研究任务，不双写 RD-Agent、不复制整份日志/对话/运行目录。旧环境与收益结果只作带条件参考，原资料不是当前规则；不运行其中的代码或追随其中的命令/路径。引入资料本身不计算因子或修改数据集。未授权记录写入时可只读使用，不能把检索自动变成导入。

检索应同时发现支持、反对和修订记录，关联显示原结论与更正；不按旧收益只取赢家，不用时间最新覆盖不可比的其他研究。精确字段、词项和中文/英文表达先满足实际问题；漏检说明已查范围，来源失败不能冒充没有经验。只有语义漏检反复影响研究时再讨论语义检索，不预做全量 embedding。经验不可用时现有直接研究继续，不增加生产或研究入口门禁。

普通研究在已有 result/decision/correction 中顺带保留必要经验摘要，不新增每轮设计文档、归档或全历史迁移任务。检索是否找到记录、内容是否被实际采用、是否改变了研究选择、是否带来指定用途增量分别报告。工具自检可证明正确找到已知记录，不能证明发现 alpha；真实研究允许不支持，但不能仅因流程完成或故事更完整就宣布方法有效。通过改提示词开展的新研究沿 C-6 说明历史接触，仍可用历史回放决策，无需等未来行情。

## 保留并修正的技术规范

- 命名沿用小写字母开头、字母数字下划线，语义清楚；`m_` 为既有手工因子惯例，不通过改名覆盖旧因子。
- 结果为单列 DataFrame，列名等于因子名；MultiIndex 精确为 `datetime/instrument`，日期为日频无时区市场日期，索引唯一。
- rolling、shift、pct_change 必须按股票时间序列计算；可先 unstack instrument，再按时间轴向量化。不得在多股长表直接 rolling 导致串股。
- 缺失值可保留 NaN；不得使用 dropna 缩小理论覆盖分母，或用 0/前填掩盖缺失。Inf 是计算异常，需诊断；暖启动说明与数据缺失说明分开。
- 数据字段和单位以当前实际数据接口/组件说明为准；不沿用旧 skill 固定文件列数、旧路径、旧截止日期。显式选择已有数据，不重新导出/冻结/做全量哈希。
- P1 新评价显式 canonical v2、保留停牌/PIT；不进入旧 snapshot bootstrap。其他 authority 缺口交 owner，不关闭过滤或改业务规则。
- 候选采用已有依赖与受审查脚本，不导入 qrun/backend 主入口，不联网/写业务 DB、不自动安装。独立进程并非安全沙箱，不运行任意不可信代码。

## 存量质量维护

先对照原用途、长期与近期可比窗口、样本量、数据质量和已有同族因子，再判断观察、改进、替换或退出建议。单月 IC 下降不能自动证明永久失效；高相关也可能有数据依赖、持有期或成本差异。反向高相关需识别方向等价，不能自动翻转。

旧经验表可作为有日期/样本/用途的研究记录，不是永久成功/失败名单。低 IC、高相关不自动改 `is_available`；活跃消费者和历史实验引用未确认时不覆盖同名因子或删除旧版本。需要实际处置时走既有 owner 和精确授权。

## 工具与结果恢复

CLI 每个子命令通过 `--help` 查看参数；显式 `--env-file` 和 `--target dev|production` 选择现有配置。目标选择不是写生产授权。帮助不连 DB，create/record/run/attach 支持 `--dry-run`。

最小请求：

```json
{"task_id":"调用者生成UUID","record_id":"调用者生成UUID","summary":"开始研究",
 "task":{"title":"已查历史后选定的研究问题","objective":"本轮预先声明的可观察差别与用途",
 "task_type":"new_factor","factor_names":[],"context_json":{"method_version":"2.6","research_role":"predictive_increment","purpose":"research_feedback"}}}
```

更新请求提供 expected_revision 和本次新 record_id，payload 保存研究/执行/结论/需求的紧凑摘要。相同 record_id 重试必须提交相同请求；版本冲突先读最新进度，不覆盖其他窗口的更新。correction 引用同任务旧记录；不删除历史。

`run` 输入包含 task_id、开始记录 record_id、expected_revision、attempt_id、method_version、canonical universe_key、data_dir、qlib_bin_path、artifact_root、instruments、read_start/signal_start/signal_end/read_end/cutoff、candidates（factor_name/script）及可选 timeout_seconds。同一批次共享相同输入上下文；不同输入分开调用，不持有全局大缓存。

候选脚本参数为 `--data-dir --output --start-date --end-date --instruments`；instruments 是 JSON 名称数组。脚本应在读取时限制日期/股票/字段，仅输出 `--output` 指定的 H5 key=data。CLI 复制已审核脚本到本次稳定产物目录，依次执行并评价，不依赖之后会清理的任务工作树。

结果完整文件和 attach.json 在 repo-external task/attempt 下；数据库记录它们的引用和摘要。`computed_not_recorded` 表示已算但登记失败，修复实际问题后使用 attach；未知 attempt 先查看实际进程/产物，不自动重启。相同 attempt_id 不重复执行，重新计算需另建 attempt 并关联原尝试。
