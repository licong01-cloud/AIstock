# BUG-1998 LocalSIM 历史回放逐日收盘估值

## 问题与责任边界

2026-10-20 用户重启后的只读核查确认：新 LSTM、TCN 账户存在成交、现金和持仓，但既有逐日资产快照通常停留在 09:33 或 09:34。历史执行器完成撮合持久化后直接返回，生命周期 owner 据此推进日期，没有接续原生收盘估值。严格收益口径不能把盘中快照认作收盘序列，因此相关日收益在工作台保留 UNKNOWN。

本修复只接续 LocalSIM 的原生估值和投影能力，不改选股、撮合、费用、账户、订单与账本算法，不修造生产历史记录，不改 FAILED_TERMINAL 或断点，不启动新回放。

## 最小修复

1. 历史执行器确认原日期、原专属绑定的撮合已完成后，要求同一 run 完成 15:00 收盘估值及持久化投影，才向生命周期 owner 返回成功。文件输入上下文覆盖该估值过程，不切换数据源。
2. 调度器仅处理参数闭合的原 run，复用现有终态估值入口。历史来源从同一 run 的原生订单读取原订单，以恢复后的账户与持仓估值；不再次提交订单。估值截止时点显式传入持久化器，不冒用实时撮合运行时钟。
3. 估值刷新不再要求新成交与新现金流水，但须证明原投影与当前数量、现金一致。无订单日期须同时具备原生 no-rebalance/阻止下单证据、零订单/状态/经济代、broker_called=false，且同一组合日期尚无其他 Paper run。
4. 普通持仓必须具有 D 日真实 15:00 分钟收盘标记。合法停牌继续接受原生验证过的停牌参考价与历史身份，不制造分钟线、价格或估值。缺少收盘标记时不推进日期，也不覆写原终态快照。
5. 已完成的同一代收盘投影可幂等复用。投影发生原生可重试连接故障时，沿现有 outbox 恢复同一已提交代，不再次成交、计费或新增经济代；非重试错误仍遵守原合同。
