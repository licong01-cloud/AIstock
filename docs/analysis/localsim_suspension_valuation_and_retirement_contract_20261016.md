# LocalSIM 停牌估值与旧内存提交核销合同（BUG-1929）

## 身份及边界

本合同承接两账户长任务计划，只修复 LocalSIM 原回放的合法停牌处理及可证明的内存提交退休。原任务与成功历史不变；不修改共享评分、冻结股票池、交易价格、订单和账本定义。

## 停牌交易资格与估值

1. 全天停牌必须来自原生 `market.suspend_d`，S 且无时段限制；部分时段停牌、未知或冲突事实不能视为全天停牌。
2. 对完整停牌事实，先走原生交易资格过滤，不能为了提交停牌意图而强制加载有效交易 pre_close/minute bars。
3. 原生 frozen pre_close 有效时保留现有估值来源。无有效 pre_close 时，估值采用单独的 `SUSPENDED_REFERENCE_CLOSE` 来源：通过现有 `load_reference_prices` 获取截止 C 已知的真实 raw 收盘报价，保留报价日、截止日、可用性合同、完整停牌事实与 hash。
4. 不读取 D 日未来收盘报价，不将估值参考写回 pre_close，不反推涨跌停，不使用成本价、旧盘中 mark 或虚构报价。普通可交易股缺交易价、无权威估值参考、可用性合同缺失/冲突时继续失败。
5. 估值字段进入原生 mark/economic evidence；兼容旧 mark 的既有 hash，不能因新增空字段破坏成功历史的身份。

## 内存提交核销

所有条件必须同时满足：纯 `local_sim` 历史失败日、原任务/日历/绑定/原计划/原证据身份完整；原失败为精确的提交前持久化错误且 `economic_commit_staged=false`；所有旧句柄一一对应原计划意图且均为原生 LocalSim 句柄；实际经济表、执行状态、economic receipt、outbox、projection receipt 等不存在未核销事实；无 UNKNOWN、QMT、在途租约或并发经济 writer。

核销在原 `recover_terminal_replay` 经济锁及原子事务内执行，绑定检查摘要和版本。保存完整原证据、句柄集合摘要、原计划意图摘要、事实检查与核销原因，不把原来“存在句柄”的历史改写为“从未提交”。scheduler 只有验证这份收据后才可重建该失败日；重建前再读实际事实，任何新事实导致拒绝。

只认完整原生证据；七类表为零或 `broker_called=false` 均不能单独构成核销依据。对于证据不足的历史记录，继续 BLOCKED 并报告缺口。
