# LocalSIM分钟行情缺失后的正式恢复合同修复

日期：2026-10-20。BUG-1996，Issue #6383。

## 原因及消费侧修复

两个原任务失败时均由DB_HISTORICAL原生入口报告`historical DB returned no minute bars`。现有恢复合同只接受精确的pre_close错误和特定停牌错误，所以即使数据owner已补齐分钟线，仍停在FAILURE_UNSUPPORTED。

本修复仅增加该精确DB错误的消费侧识别。继续验证原账户、原日期、原日历、原数据源和策略/计划/评分冻结身份、账户无其他在途任务、七类经济事实全零、无未证明副作用及有效租约。每次检查重新调用原生行情入口；正式recover仍由事务、版本和快照摘要CAS保护。不扩展至实时或文件源，不接受模糊错误字符串，不放宽真缺数据、价格、停牌或副作用校验。

按既有流程注册目标模块自有的纯恢复响应校验，只在原生输入匹配原交易日、已具备有效价格和分钟线（或合法停牌估值证据）且经济事实全零时通过。单纯HTTP 200或ready=false不能作为本修复的运行验收。两个脚本仅负责既有机制的登记/委托，未改变门禁规则。

## 多轮审核与验证

第一轮复核精确故障边界；第二轮复核冻结身份、真实缺口、七类经济事实、原事务CAS及重复检查；第三轮核对真实数据读回和运行语义，拒绝旧响应、错误日期、未知源、非法价格/数量和HTTP假成功。既有恢复回归与新增定向合同在最终提交前执行，工作流登记执行workflow-smoke，CI使用最终HEAD。

DESIGN-COMPLIANCE-001逐项结论：交付为原正式恢复入口的完整修复；无静默错误或伪造数据；不改变交易/账本、资金和已冻结政策；只复用既有恢复与重启验收控制，没有新增人工审批。
