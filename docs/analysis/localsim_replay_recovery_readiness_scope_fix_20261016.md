## 门禁与原子合同

1. GET recovery 与 POST recover 使用专用恢复前置检查；复用原生全局只读 readiness。关系、外键、账本范围、旧产品残留、血缘及未知门禁仍全部拒绝，仅将可识别的全局在途计数交给目标账户检查。
2. 原生恢复快照按原 job 的 `simulation_account_id` 读取该账户的所有在途日运行，包含跨后端异常事实；不以示例包、账户白名单、日期或请求开关过滤。
3. 缺少完整账户活动查询结果时返回 `LOCALSIM_REPLAY_RECOVERY_ACCOUNT_ACTIVITY_UNKNOWN`；目标账户有在途运行时返回 `LOCALSIM_REPLAY_RECOVERY_ACCOUNT_RUN_IN_FLIGHT`。这些事实进入原 snapshot 摘要。
4. POST 保留原 job/run、经济锁、版本及摘要 CAS、完整副作用检查、恢复谱系和回读。快照重查同时锁定原账户，锁顺序与原生后继流程一致；在锁内重新读取账户活动后才允许恢复。旧摘要不得跨版本合同复用。
5. 恢复不直接发单，不改其他账户状态。原任务恢复后由既有生命周期 owner 执行。全局 `require_ready`、catch-up、safe-boundary、最终实时激活路径保持严格原合同。
6. 合法停牌估值与旧内存句柄核销继续使用 BUG-1929 的完整合同；普通真缺价、S/R 事实冲突、未知副作用保持显式阻塞。
