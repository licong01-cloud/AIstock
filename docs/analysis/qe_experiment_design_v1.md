# QE实验设计（原组合配置）重构与升级详细设计方案

## 1. 核心业务逻辑与现状分析

### 1.1 回答您的核心问题：QE自动演进是否必须基于现有实验？
在原生的 RDAgent 架构中，演进（Evolution）本质上是对一段**已有代码和运行轨迹（Trace）**的不断迭代（提出假设 -> 修改代码 -> 运行评估 -> 反馈）。因此，从底层逻辑上说，演进确实需要一个“基座（Base Experiment）”。
**但是，这并不意味着只能从历史完成的实验开始。**
为了实现您要求的“从零选择因子、模型、策略并启动演进”，我们的系统将在后台自动进行一次**冷启动组装（Cold Start Assembly）**：将您选中的因子代码、模型代码、策略代码在 WSL 中动态拼装成一个“初始实验（Task 0）”，然后将这个“Task 0”作为基座，无缝触发 RDAgent 的后续自动演进（Loop 1, Loop 2...）。

### 1.2 核心改造目标
1. **页面重命名与UI重构**：“组合配置”全面更名为“QE实验设计”，整体色调、卡片阴影、字体排版严格对齐现有的“自动演进”页面。
2. **双轨驱动入口**：支持“AI智能生成配置”与“人工分步流程式选择”双轨并行，互不冲突。
3. **组件高复用**：因子、模型、策略库的 UI 组件实施高度复用，转为“选择模式”（Selection Mode）。
4. **任务分流**：配置完成后，支持分流为**独立任务（单次回测）**与**QE演进任务（循环迭代）**，且两者均可在“自动演进”看板中统一监控。

## 2. 页面整体布局与 UI/UX 设计

### 2.1 顶部：AI 智能实验设计区
- **标题**：AI 智能实验设计 (AI Smart Experiment Design)
- **UI 元素**：
  - 一个开阔的文本输入域（Textarea），引导语：“请输入您的实验设计目标，例如：构建一个偏向于动量反转的日频量化组合，配合高频微观结构因子，要求夏普比率大于1.5...”
  - **“智能生成配置”按钮**（带酷炫的 AI Loading 动效）。
- **交互逻辑**：点击生成后，调用后台 LLM API 解析意图。解析成功后，**自动锚定并高亮**下方人工配置区对应的因子、模型和策略复选框，用户可继续在此基础上微调。

### 2.2 中部：全链路选择流程图（Stepper组件）
- **UI 元素**：横向步骤条（Step Navigation）。
- **节点**：`1. 因子选择` -> `2. 模型选择` -> `3. 策略选择` -> `4. 组合配置` -> `5. 生成执行 (WSL)` -> `6. 结果查看`
- **交互逻辑**：支持点击任意已激活节点进行无损跳转（不丢失已选数据）。

### 2.3 下部主体：人工配置分步卡片区（复用库组件）
- **通用设计规范**：
  - 各步骤底部提供“上一步”、“下一步”按钮。
  - 列表呈现形式必须为**卡片（Card）**，保持与知识库、因子库高度一致的数据来源标识、指标标签和颜色。
  - 去除原有的“批量分析”、“回测”等直接操作按钮，在卡片右上角或左侧统一增加**复选框（Checkbox）/单选框（Radio）**。
  - 默认分页：每页 20 条，支持自定义。

#### 步骤 1：因子选择 (Factor Selection)
- 完全复用 `<FactorList />` 组件，传入参数 `mode="selection"`。
- 支持多选，选中的因子将在页面底部或侧边栏提供一个“已选清单（抽屉或悬浮球）”展示。

#### 步骤 2：模型选择 (Model Selection)
- 完全复用 `<ModelList />` 组件，传入参数 `mode="selection"`。
- 支持单选（通常一个实验对应一个核心主模型，若支持多模型 Ensemble 则开放多选）。

#### 步骤 3：策略选择 (Strategy Selection)
- 完全复用 `<StrategyList />` 组件，传入参数 `mode="selection"`。
- **特殊功能**：将策略划分为两个独立的可选区块：
  1. **日频策略区 (Daily Strategies)**：单选或多选。
  2. **日内高频策略区 (Intraday High-Frequency Strategies)**：单选或多选。
- 允许用户同时勾选“日频”与“日内高频”，满足组合策略需求。

#### 步骤 4：组合配置与 AI 评估 (Portfolio Assembly & Evaluation)
- **展示已选项**：清单式列出选中的因子（List）、模型、日频策略、高频策略。
- **“AI 评估组合”按钮**：点击后，LLM 对当前所选组件的合理性、数据频度匹配度、过拟合风险进行文字版评估，并生成一份“组合分析报告（Markdown格式卡片展示）”。

#### 步骤 5：任务下发设置 (Task Dispatching)
提供两个巨大的分支选择卡片：

##### 分支 A：运行独立任务 (Run Independent Task)
- **定义**：单次生成 Qlib 配置并执行，不进行代码演进。
- **输入**：实验名称、回测时间区间设置等基本参数。
- **按钮**：“生成配置并执行”。

##### 分支 B：发起 QE 演进任务 (Start QE Evolution Task)
- **定义**：以此配置为基座，触发 RDAgent 的因子或模型演进循环。
- **保留旧功能**：提供一个“从现有完成实验继续演进”的下拉菜单（复用旧逻辑）。
- **输入项**：
  - **演进目标 (Evolution Goal)**：如果是 AI 自动生成的，这里自动填充 AI 理解的目标，允许人工修改。若是人工配置，需必填。
  - **Loop 数量 (Max Loops)**：如输入 3 或 5。
  - **演进方向**：单选（因子演进、模型演进、混合双料演进）。
- **按钮**：“启动自动演进”。

## 3. 需补齐的系统限制与后端 API 缺口

要完美实现上述前端设计，我们需要在后端（FastAPI + 数据库）和底层（WSL + RDAgent）补齐以下功能：

1. **AI 智能设计接口 (`POST /api/experiment/smart-design`)**：
   - 接收用户的自然语言需求。
   - LLM 需要能够检索当前数据库中可用的因子池、模型池、策略池，返回匹配的 ID 列表。
2. **AI 评估组合接口 (`POST /api/experiment/evaluate-portfolio`)**：
   - 接收选中的因子、模型、策略元数据，输出专业的投资组合分析报告。
3. **冷启动组装引擎 (Cold Start Workspace Builder)**：
   - 当用户选择**新组件**并点击“独立任务”或“演进任务”时，后端需要一个脚本：
     - 根据选中的因子、模型、策略，动态生成 `workflow_config.yaml` 或拉取对应 `.py` 文件。
     - 在 WSL 中初始化一个新的独立运行目录。
4. **独立任务的统一看板兼容 (`GET /api/evolutions`)**：
   - 目前“自动演进”页面只展示树状的演进任务。我们需要在数据库中增加一个 `task_type` 字段（`evolution` vs `independent`）。
   - 独立任务在演进页面中展示为**单节点任务**，同样可以查看日志、图表、持仓和回测结果。

## 4. 给您的合理化建议

1. **关于日频与高频组合的底层支持：**
   - **建议**：目前 Qlib 对同时混合跑日频（Daily）和日内高频（Tick/Minute）的数据处理管道是分离的。如果强制在 UI 允许它们组合，WSL 底层必须有一套 **Meta-Controller（元策略控制器）**，比如用日频模型决定大类仓位，用高频模型执行具体买卖点（Execution）。如果在底层 Qlib 侧这一块的 Python 胶水代码还没准备好，建议在初期提示“当前底层执行环境暂未就绪，该组合将分别回测”，或优先在底部实现该胶水逻辑。
2. **关于前端组件的复用：**
   - **建议**：为了绝对保证样式和数据的统一，不要复制一份因子库代码。我们应修改现有的 `FactorList.tsx`, `ModelList.tsx`, `StrategyList.tsx`，给它们增加一个属性 `<FactorList mode="selection" onSelect={handleSelect} selectedIds={selectedFactorIds} />`。如果是 `selection` 模式，就隐藏右上角的操作按钮，显示勾选框。
3. **关于保留“从现有实验演进”：**
   - **建议**：在“分支 B：发起 QE 演进任务”中，我们可以提供一个 Toggle 选项：`[ 从新组合冷启动 ]` vs `[ 从历史实验延续 ]`。如果点击后者，直接隐藏上方的分步选择器，弹出一个下拉框让用户选历史 `trace_id`。这样既满足了新功能，又保留了您要求的旧功能。

## 5. 需要您明确/回答的细节问题

在动手写前后端代码之前，为了避免南辕北辙，请您帮忙确认以下几个底层细节：

1. **独立任务执行器 (Independent Runner)**：对于“独立任务”，我们是直接在 WSL 里拼凑一个标准的 `qrun xxx.yaml` 命令，还是依然使用 RDAgent 框架，只让 RDAgent 跑 0 个 Loop？（推荐后者，这样日志、图表、数据结构能和演进任务完全保持一致，前端极好兼容）。
2. **历史实验代码拉取**：从零选择因子和模型后，底层组装“初始工作区”时，是否已经有了将特定因子 ID 和模型 ID 的 Python 源代码从数据库或文件系统提取并注入到 Qlib 实验目录的标准化脚本？如果没有，我需要在本次开发中一并实现。
3. **高频+日频的融合执行**：底层 WSL 中的量化引擎，目前是否已经跑通了“日频+高频”结合的策略逻辑？如果底层跑不通，UI 开放选择后在执行阶段会报错。
4. **UI 主题同步**：自动演进页面的风格目前是深色科技风还是浅色极简风？请确认我们以目前系统的哪个路径下的 CSS/Theme 为基准进行对齐。
