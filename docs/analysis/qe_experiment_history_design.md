# QE实验历史页面与同步/删除功能详细设计方案

## 1. 现有程序的架构和执行流程分析

### 1.1 实验生成与执行架构
1. **组合与生成**：用户在 QE 前端通过各项 Agent 分析后选定因子、模型和策略，向后端发起实验组合请求。后端 `ConfigComposer` 将因子代码、模型配置、策略参数整合成标准的 RDAgent (QLib) 执行配置。
2. **工作空间创建**：后端在 RDAgent 侧（WSL 环境）创建一个唯一的实验工作目录 (`workspace_path`)。
3. **执行流程**：后端生成执行脚本（包含数据准备、因子计算、模型训练、策略回测等环节），并在 WSL 中运行该脚本。
4. **状态与存储**：实验信息被记录在 AIstock 数据库的 `qe_experiments` 表中，包含状态（`status`：如 created, running, completed, failed）、WSL 路径 (`workspace_path`)、使用因子、模型、策略等信息。

### 1.2 现有的“同步”流程
目前在 `config_composer.py` 中的 `sync_experiment_results` 方法，主要是去实验目录（`exp_dir`）读取已经生成的回测结果文件 `qlib_res.csv` 和其他性能指标（Metrics），将这些纯文本统计数据写入数据库的 `result_metrics` 字段中。**并没有**真正将体积较大的模型权重文件或特征配置文件从 WSL 的 RDAgent 侧持久化转移到 AIstock 的标准存储资产库中。

## 2. 需求分析：缺失功能与前提限制

### 2.1 缺失功能
1. **前端 UI 卡片化显示与配色**：当前的 `/quantevolver/experiments` 页面虽然展示了列表，但 UI 缺乏与“模型库”一致的卡片化设计、字体配色以及明确的状态（是否已同步）标签。
2. **模型文件与特征文件的物理同步**：需求要求不仅同步指标数据，还要把**训练的模型权重文件**和**模型特征值入口顺序文件**同步到 AIstock 侧。目前后端完全没有处理这部分实体文件的复制或归档逻辑。
3. **级联安全删除逻辑**：目前没有任何删除实验的功能。需求要求二次确认后：
   - 通过 RDAgent API 删除 RDAgent 侧 WSL 中的实验目录和所有文件。
   - 删除 AIstock 侧对应的实验目录（存放同步文件的目录）。
   - 删除数据库中的实验记录。
4. **实验详情的可视化展示**：现有前端没有一个完整的“详情页/弹窗”，无法让用户一目了然地看到该实验所用的“具体因子列表、模型名称、策略及全部回测指标详情”。

### 2.2 前提限制与具备条件
1. **文件访问与API权限（具备）**：AIstock 后端可以直接通过 WSL 绝对路径访问 RDAgent 目录，或者由于需求明确提到“通过 RDAgent 的 API 删除”，我们需要在 RDAgent 侧实现或利用已有的文件/目录删除接口。
2. **模型产出文件的确定性（限制）**：我们需要明确 RDAgent (QLib) 训练完成后，**模型权重文件**（如 `.pkl`, `.bin`）和**特征文件**的具体命名规则和存放位置（通常在实验工作区的 `models/` 或根目录下）。必须确保这些文件在同步前确实已经生成完毕，否则同步会找不到文件。
3. **数据库字段支持（具备）**：现有的 `qe_experiments` 表可以利用 `status` 或 `result_metrics` 中的 JSON 结构来标记 `is_synced: true`，无需修改表结构即可实现“是否已同步”的状态展示。

## 3. 详细设计方案

### 3.1 前端 UI 改造设计 (Frontend)
- **页面布局**：将现有的列表重构为 Responsive Grid（网格）布局，采用与“模型库”一致的卡片（Card）样式、字体和背景配色。
- **卡片设计**：
  - **头部**：左侧显示实验名称（加粗大字体），右侧显示执行状态和同步状态的彩色 Badge（如：绿色的“已完成”，紫色的“已同步”）。
  - **主体**：简明展示该实验的执行时间（耗时或更新时间），以及是否已经同步数据到 AIstock 侧。
  - **底部操作区**：
    - `同步数据` 按钮（带 Loading 效果的图标按钮，如果已同步可置灰或变为“重新同步”）。
    - `查看详情` 按钮（如果实验执行成功才可用）。
    - `删除` 按钮（红色图标或文字，点击触发二次确认弹窗）。
- **删除确认弹窗 (Modal)**：
  - 标题：“确认删除实验？”
  - 提示文案：“此操作将永久删除该实验在数据库中的记录，同时彻底清理 RDAgent (WSL) 及 AIstock 本地的物理实验目录和模型文件，操作不可恢复！”
  - 动作：确认执行删除接口，取消则关闭。
- **详情展示抽屉/弹窗 (Drawer/Modal)**：
  - 点击“查看详情”后弹出。
  - 模块划分为：**基本信息**（状态、耗时、路径等）；**组合明细**（详细的因子名字列表 tag、模型详情、策略参数 JSON 展开）；**回测表现**（指标网格，包含 IC, 年化收益等更详细统计数据）；**资产文件**（列出同步成功的权重和特征文件名）。

### 3.2 后端数据同步机制 (Backend - Sync)
- **接口**：增强现有的 `POST /experiments/{experiment_id}/sync-results`。
- **逻辑增强**：
  1. 维持现有的指标提取逻辑，把详细分析统计数据保存到数据库中。
  2. **定位实体文件**：在 WSL 实验工作区路径 (`workspace_path`) 中扫描特征顺序文件（例如 `features.pkl` 或 `instrument_features.txt`）和模型权重文件（如 `model.pkl`）。
  3. **目标路径设定**：在 AIstock 侧设定统一的实验资产存放目录，例如 `f:/Dev/AIstock/rdagent_assets/qe_experiments/{experiment_id}/`。
  4. **文件复制**：将 WSL 里的特征和权重文件复制到 AIstock 的上述目录中。
  5. **记录状态**：在数据库的 `result_metrics` JSON 中写入已同步文件的路径和标志位 `"is_synced": true`。

### 3.3 后端删除级联流程 (Backend - Delete)
- **新接口**：增加 `DELETE /experiments/{experiment_id}`。
- **逻辑流程**：
  1. 查询数据库获取实验详情，获取其 WSL 执行目录 `workspace_path`。
  2. **调用 RDAgent API 清理 WSL 侧文件**：由于需求明确要求“通过 RDAgent 的 API 删除”，AIstock 需要调用 RDAgent 的相关 HTTP 接口（例如 `DELETE /api/workspace?path=...`）彻底清理 WSL 中的实验目录和所有文件。
  3. **清理 AIstock 侧实验目录**：如果之前发生过同步，清理 `f:/Dev/AIstock/rdagent_assets/qe_experiments/{experiment_id}/` 目录。
  4. **清理数据库**：执行 `DELETE FROM qe_experiments WHERE experiment_id = %s`。
  5. 返回操作成功。

### 3.4 API 设计与依赖检查
- 需要确认 RDAgent 侧是否已经具备按路径删除工作区目录的 API。如果不具备，需要在后续开发中在 RDAgent 端补充该接口。
- 需要明确实验生成物中，模型权重和特征值的准确相对路径与文件名约定，以确保同步逻辑能够准确捕捉到所需文件。
