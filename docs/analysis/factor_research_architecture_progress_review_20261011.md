## 1. 审核要解决的问题

核心问题不是“流程是否完整”，而是：当前架构和研究方式能否帮助发现有用途、有增量的因子；为什么近期完成多轮研究，仍没有形成正式推荐的新因子？

当前判断分三层：

- **事实**：完整评价、局部相关、用途比较、研究记录和请求级多期限能力已经存在；下述近期新候选尚无正式推荐，存量因子用途及替换线索仍有保留。
- **分析**：工具提高了错误识别能力，但没有足够证据证明新因子的发现效率提高；选题和表达仍较多围绕相近的价量、波动、换手等信息。
- **待审建议**：优先识别现有方法未解释的市场现象，再构造少量候选；加强选题时对既有结果的实际使用。不因此新增平台、数据源、准入门禁或自动淘汰规则。

审核可以推翻这些分析。不能因双方形成共识，就认定 alpha 存在或方法论有效。

## 3. 当前程序架构

### 3.1 主链与三对象分离

```text
Codex / Claude Code：提出假设、实现受审查候选、解释结果
  │
  ├─ list/show/context/memory-search ── 研究历史、官方摘要只读引用
  ├─ experience/proposal-prepare/proposal-inspect ── 辅助材料与合同核对
  │
  └─ create/record/run/attach
       ├─ ResearchRepository ── 研究 tasks / records（选定 DEV 或生产目标）
       └─ ResearchService → runner
            ├─ 候选子进程或复用已审核 values → 仓库外研究产物
            ├─ QE shared prepare/compute → 独立指标、多期限预测
            ├─ full_evaluation → 历史/近期窗口、候选相关
            └─ comparison → B 与 B+F / 替换 / 交互的研究比较

用户批准后，另走正式交付：正式源码/catalog → 官方缓存/指标/相关/分类/评级
QE 真实策略验证：交 QE owner；不由研究 run 自动启动
```

三个对象独立：**研究候选/结论、官方单写指标、生产因子目录**。研究任务 completed 或 run computed 均不表示因子有效、生产晋升或 QE 已验证。

### 3.2 代码定位与实际能力

下表路径除 CLI 外均相对 `backend/services/factor_research/`；责任模块以 `tests/aistock_validation/catalog/file_ownership.yaml` 的 `factor_library.research` 为准。

| 层 | 代码与入口 | 已实现能力 | 不应声称的能力 |
|---|---|---|---|
| CLI | `scripts/factor_research.py::parser/dispatch` | create/list/show/record/context/run/attach/quality/memory-search，以及 experience/proposal-*、salvage-* | 不是后台调度器，也不是自动研究代理 |
| 研究记录 | `repository.py::ResearchRepository`；`models.py` | tasks 当前投影、records 追加记录；record_id 幂等、revision 乐观并发；只读事务；无 import 建表 | `--target production` 不等于获准写生产；数据库有历史不等于所有经验都被检索到 |
| 执行与恢复 | `service.py::run/attach` | 先登记 attempt，再执行；computed_not_recorded 可 attach 而不重算；核对请求、候选和产物归属 | 不从成功计算推导正确结论；不自动晋升 |
| 数值执行 | `runner.py::validate_spec/execute`；`candidate_subprocess.py` | 显式股票、日期、数据目录；受审查脚本子进程；可用 values_artifact/reuse_basis 复用；仓库外结果 | 子进程隔离不是安全沙箱；候选代码仍须审核，不能执行任意历史代码 |
| 官方摘要上下文 | `service.py::context`；`comparison_context.py` | 指定因子的表达式、官方摘要、相关性摘要；词法输入依赖与本次返回行内 Jaccard 提示 | 不是全库自动近邻搜索；动态依赖仍 unknown；查询日期是 calculated_at/as_of_date，不自动等于评价样本日期 |
| 研究经验检索 | `memory.py`；repository 的 memory 查询 | 因子名/字段/词项匹配、条件过滤、分页及关联更正记录 | 不是向量 RAG；未命中不等于历史从未研究；不能把相似描述判为同一金融机制 |
| RD-Agent 辅助 | `assistance.py::experience/prepare_proposal/inspect_proposal` | 读取声明范围的参考资料、准备交接包、检查提案；历史来源与当前数据依据分开 | prepare 不调用模型、不生成实际因子、不运行 RD-Agent；不证明所有历史 RAG 经验已导入 |
| 旧因子抢救 | `rdagent_salvage.py` | 盘点、代码归组、准备适配、预检、评价与参考相关入口 | 同名不等于同代码；旧数据集/旧收益不能当本轮评价证据；不修改 RD-Agent 程序 |
| 完整研究评价 | `full_evaluation.py::build_standard_windows/compute_candidate_metrics/compute_correlation_views` | 共享指标、多窗口；候选×参考及候选内部对；参考分批读取，复用逐日相关 | 不重算参考×参考；不表示实时生产目录全库已核对；相关窗口不按每个持有期限重复计算 |
| 用途比较 | `comparison.py::compute_comparison` | 同规则分别拟合、配对 RankIC 差、偏 RankIC、HAC、张成/相似性诊断及覆盖报告 | 不是通用交易回放；内置 conditional 为排名预测交互，不是任意状态损失或执行策略引擎 |
| 存量质量诊断 | `quality.py`、`quality_repository.py` | 读取已有指标/相关和月度证据，给诊断 | 不自动删除、降级生产因子，不是官方评级 writer |

研究表为 `public.factor_research_tasks`、`public.factor_research_records`，migration 在 `backend/migrations/factor_research_p1_20260908.sql`。本轮只核对源码，不重新证明 DEV/生产 schema 状态。JSON 承载研究角色、依据与条件，不为每个研究主题新增表。

研究库是研究进度与决策历史的权威；repo 外数值、脚本和报告是可定位的计算产物。即席分析脚本、文字结论与数据库登记并非自动等价：需要实际写入并 readback，不能保证每句对话或每个临时探索都已记录。

### 3.3 共享能力与所有权

- `backend/services/quantevolver/qe_eval_v2_metric_engine.py` 属于 QE 共享能力。研究 runner 调用 `prepare_shared_context`、`compute_single_factor_metrics`，不另造标签/官方评价引擎。
- `full_evaluation.py` 调用既有 `CorrelationEngine.compute_selected_daily_submatrix`，不是依赖名字可能误导的 `compute_incremental` 去重算全矩阵。参考值未提供或不可比较必须单列。
- 正式保存复用 `ManualFactorService.save_factor` 等入口；同名保存可能覆盖，研究写入不能偷偷转成正式保存。官方指标、相关、分类、评级分别交各自流程。
- QE/数仓、数据准备、评级语义缺口交 owner；本窗口不得因研究方便跨模块改动、导出数据、激活 profile、修改 RD-Agent 或启动 QE。

### 3.4 现存能力边界，需审核者特别注意

1. 研究多期限是请求级 `holding_periods=[1,5,10,20,40,60,120,240]`；不传时保留四周期默认。显式请求启用 `include_horizon_metrics=True`，并保留 `label_calendar`、映射及 `horizon_support`。comparison 每个请求声明一个目标期限，不能把一次比较说成八期限全部比较。
2. 长周期扩展是预测评价，没有实现长周期真实持仓路径、净收益或夏普。旧 top_* 是兼容的 1 日分组统计，不能改名当 60/240 日策略结果。
3. 当前 `memory.py::FILTER_CHOICES.horizons` 仍为四周期。八期限 run 已支持，不代表经验过滤也升级；长周期历史可用关键词/任务读取，但没有八期限过滤能力。`assistance.py` 的部分提示文字仍写四周期，也不代表所有旧辅助合同已经扩展。
4. `comparison.py` 的主要自动对照是日期平衡的排名 OLS。行业广度 Brier 等研究使用各任务脚本，并非共享比较器已经覆盖所有角色损失。换用另一模型可能改变结论，不能将该比较等价于 QE 所有模型。
5. `_cost_report` 需要现成权重/收益路径，不生成可执行路径。未提供时缺的是该用途的成本证据，不是自动证明因子无价值。
6. 全目标历史 PIT 是研究合同，不能仅凭给参数列表就宣布满足；应核对该任务的池来源、区间、预热、缺失及实际分母。通用 runner 本身可接受显式子范围，技术预检与正式完整评价须区分。
7. 原始全样本 RankIC 与控制变量齐全样本的偏 RankIC 不是天然可比。`_partial_rank_daily` 同时提供 `raw_rank_ic_on_control_sample`；审核还需匹配有效日期，不能将两种均值直接相减解释成“被基准解释的比例”。

## 4. 当前评价口径

### 4.1 角色与结论

| 角色 | 应回答的问题 | 不能统一套用的否决 |
|---|---|---|
| 新增预测信息/表示 | 在声明的 B、用法、历史比较下，F 是否提供增量？ | 低原始或偏 RankIC 不否定所有事先声明的非线性/交互 |
| 替换改进 | 相近信息是否更稳定、低成本、覆盖更好，或在指定方法中更有效？ | 残差接近零不等于替换无价值 |
| 状态/条件变量 | 对指定决策或损失是否有帮助，同时看参与和漏掉机会？ | 不因自身横截面 IC 低而直接否定 |

报告分“信息关系”与“使用价值”两轴。低相关、表达式不同、评级高、审核通过不构成 alpha 证据；同源、已知变换、负 IC 也不自动等于无用。高张成度只描述方差解释，不排除小残差有预测能力。

### 4.2 样本、时间和统计

- 技术预检后，正式候选评价覆盖完整声明的历史 PIT 股票池和全有效历史，优先展示 2024 年以来、各年、近期/月度。不是只抽部分股票；任务批次和跟进复用不重复计为新候选。
- 本文近期结果使用显式 R8 `20261006-v18-unified-basicfields1`，并非宣称它是当前全局 active。路径：`X:/AIstock_dataset_candidates/backtest_dataset_candidates/20260831-qe_hmm_full_v2-direct-20261006-r8-unified-basicfields1-candidate`。
- 既有 manifest identity：`36fc14db370374dac56d68b81bbb80c5d020010c85ba7d1cde1d51b34c55cc5a`；本文引用已有标识，不新冻结、不全量哈希、不重导出。
- 数据 2018-08-01..2026-08-31，5,144 只历史 PIT 证券、1,961 个交易日；原始 PIT 机会 7,980,876，排除同源 S 停牌后 7,969,342。并非每个因子/期限均有这些有效观测，预热与配对损失另列。
- 文中 2026 均截至该数据版本；“近三个月”指 6—8 月附近的有效成熟窗口，不是当前 10 月的最新市场。2026 长周期可评价样本很少：价格延迟的 120 日仅 39 天、240 日为 0，不能借此宣布长周期更好或更差。
- 标签复用引擎返回的实际映射和完整交易日历；当前 h20 收益是 T+1 到 T+21。长周期未成熟不裁掉短周期、不填零；各期限股票/日期支持不同，不把数值大小差全归因于期限。
- 原始 RankIC 为候选排名与收益排名的 Pearson 相关；偏 RankIC 两侧对同一 Z 残差化后做 Pearson，残差不重排。行业为哑变量，零残差返回无定义，不能填成零。
- 基准/控制选择及拟合标签遵守时间边界；事后看过历史仍可做回放，但标记 research_feedback，不称未接触 OOS。不要求等待未来行情才可研究，也没有“每年每周期均正”的规则。
- 逐日期配对增量及 HAC 带宽、缺口、支持数单列；本批报告无多重性保证，不把大量股票日期视为独立实验。正式交易价值另需相应持仓、成本与约束证据。

## 6. 为什么零新增推荐：事实与待检验解释分开

| 观察 | 合理解释 | 仍不能推出什么 |
|---|---|---|
| 多个候选原始指标不错，但强 B 增量小 | 信息已部分存在于简单风格/构造输入，可能只是另一种表示 | 所有非线性模型、持有路径都无价值 |
| 成交量延续低相关而增量近零 | 新颖性与预测价值不同，复杂表达也可能主要增加噪声 | 相关性筛选没用，或所有价量方向均无效 |
| 正向假设遇到明显负相关 | 本地市场机制/代理/尺度与假设不符，或预测方向需要训练期识别 | 直接事后翻号即可认定成功；也不是负因子天然无价值 |
| 行业候选约半市场覆盖 | 当前输入支持限制判断范围 | 数据无问题或整个经济方向无效；根因仍应交数据 owner 确认 |
| 旧问题重新出现在下一轮计划 | 记录未充分转化为选题决策 | 必须新建向量平台、强制全库检索或审批 |
| 存量低换手能测到正向增量 | 当前工具与输入并非只能产出零信号 | 全部数据和评价器已经无缺陷，或未来能稳定赚取收益 |

主要分析是：研究逐渐能“排除不够好的候选”，但候选形成仍较偏向同类信息重表达；论文与金融叙事到本地现象的联系不够充分。价格延迟实现采用五交易日块、每日滚动且未额外跳过一个月，与论文不完全同构，不能将本规格负结果表述为论文被证伪。

同时要防止过度保守：方法论没有要求全部年份/期限显著、必须新数据源或必须先证明生产净收益。研究使用价值与新增来源信息分开；不能用某个线性 B 的增量不足，宣称对全部 QE 模型都无效。

计算投入也需区分：十候选报告记录独立评价含构建 358.8 秒、相关 5,631.9 秒、12 项强基准比较 1,359.9 秒；成交量延续报告记录独立评价含构建 75.8 秒、相关 2,538.2 秒。部分阶段并行，不能相加当作端到端耗时。这说明“完整计算做完了”并不是经济问题已解决，也提示要在生成候选前提高选题质量；不构成取消完整评价的理由。

目前没有前后可比的研究命中率/成本基准，不能声称新方法已提高发现效率，更不能承诺工具升级必然产生有效因子。

## 7. 建议调整的执行重点（供审核，不在本文实施）

1. **先看遗漏的现象，再决定候选**：在现有数据内定位简单基准失效的情形；明确金融机制或承认只是经验现象，说明竞争解释。不要把必须凑十个公式当目标，也不将“先看现象”包装成新门禁。

3. **完整评价要求不退回小样本定性**：技术有效的正式候选仍做全目标 PIT、全有效历史、多周期独立评价与可比参考相关；调整的是选题质量，不取消用户要求的评估范围。
4. **不全量复活旧失败项**：此前只有四周期结果不能证明长周期无效，但仅对机制和未解问题确有依据的对象讨论补评。不给已结束规格补存档、补门禁或无限参数搜索。
