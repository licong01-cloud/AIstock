## 真实根因和复现

原汇总代码先建立无序集合，再按集合顺序累加 Decimal 价格比率。集合遍历顺序受进程哈希种子影响；有限精度加法在大量计划上不满足逐字节的结合律。两次汇总的极小末位差异会改变报表字节与 SHA，现有不可变发布器正确拒绝覆盖。

专项 5000 计划、BUY/SELL 各 2500 的跨进程回归，修复前失败，修复后通过。完整真实历史输入在 PYTHONHASHSEED=1/2/3/4 下，旧函数生成四个不同哈希，修复函数均为：

`4022191bb7d38b073fcc8ec06618906c1e15ca64fa98961e4603e58f0beddd7c`

该值是完整比较行的 canonical SHA，不是原始结果文件 SHA。

真实账户来源未替换。诊断工具从原生产源码 AST 提取唯一汇总函数和完整结果组装代码，在 WSL 中读取已冻结的日结果、账户回执及源检查收据，不运行账户、行情读取或订单执行。

- 2353 个账户日、2353 个账户回执逐一核验完整文件 SHA；回执 envelope SHA、账户、交易日、日序和前缀引用匹配。
- 原完整结果组装与已发布结果仅有 5 处条件成交价差末位不同；所有账户、净值、费用、状态、数量、账户引用和其他结果字段一致。
- 修复后的稳定比较与原发布结果仅有 3 处条件成交价差末位不同，最大绝对差 `6E-26` 个基点。
- 4709 个受保护原文件的完整 SHA 在验证前后均一致。
- 四个种子的输出及完整差异均保留，未选择性删除不一致样本。

原失败进程未保存待发布结果候选，因此不声称拿到了该进程的完整候选字节。根因证据来自实际调用栈、原生产结果组装的只读复现，以及跨种子反事实验证。
