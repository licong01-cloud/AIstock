# QE实验设计（原组合配置）重构与升级详细设计方案

## 1. 核心业务逻辑与现状分析

### 1.1 回答您的核心问题：QE自动演进是否必须基于现有实验？
在原生的 RDAgent 架构中，演进（Evolution）本质上是对一段**已有代码和运行轨迹（Trace）**的不断迭代（提出假设 -> 修改代码 -> 运行评估 -> 反馈）。因此，从底层逻辑上说，演进确实需要一个“基座（Base Experiment）”。
**但是，这并不意味着只能从历史完成的实验开始。**
为了实现您要求的“从零选择因子、模型、策略并启动演进”，我们的系统将在后台自动进行一次**冷启动组装（Cold Start Assembly）**：将您选中的因子代码、模型代码、策略代码动态拼装成一个“初始实验（Task 0）”，然后将这个“Task 0”作为基座，无缝触发 RDAgent 的后续自动演进（Loop 1, Loop 2...）。

### 1.2 核心改造目标
1. **页面重命名与UI重构**：“组合配置”全面更名为“QE实验设计”，整体色调、卡片阴影、背景、字体排版严格对齐现有的“自动演进”页面。
2. **双轨驱动入口**：支持“AI智能生成配置”与“人工分步流程式选择”双轨并行，互不冲突。
3. **组件高复用**：因子、模型、策略库的 UI 组件实施高度复用，转为“选择模式”（Selection Mode）。
4. **任务分流**：配置完成后，支持分流为**独立任务（单次回测）**与**QE演进任务（循环迭代）**，且两者均可在“自动演进”看板中统一监控。

## 2. 页面整体布局与 UI/UX 设计

### 2.1 顶部：AI 智能实验设计区
- **标题**：AI 智能实验设计 (AI Smart Experiment Design)
- **UI 元素**：
  - 一个开阔的文本输入域（Textarea），引导语：“请输入您的实验组合设计目标，例如：构建一个偏向于动量反转的日频量化组合，配合高频微观结构因子...”
  - **“智能生成配置”按钮**（带加载动效）。
- **交互逻辑**：点击生成后，调用后台 LLM API 解析意图。解析成功后，**自动锚定并高亮**下方人工配置区对应的因子、模型和策略复选框，并在各卡片中自动打勾，用户可继续在此基础上人工微调。

### 2.2 中部：全链路选择流程图（Stepper组件）
- **UI 元素**：横向步骤条（Step Navigation）。
- **节点**：`1. 因子选择` -> `2. 模型选择` -> `3. 策略选择` -> `4. 组合配置` -> `5. 生成执行 (WSL)` -> `6. 结果查看`
- **交互逻辑**：支持点击任意已激活节点进行无损跳转（不丢失已选数据）。

### 2.3 下部主体：人工配置分步卡片区（复用库组件）
- **通用设计规范**：
  - 各步骤底部提供“上一步”、“下一步”按钮。
  - 列表呈现形式必须为**卡片（Card）**，保持与目前因子库、模型库高度一致的数据来源标识、显示风格、页面字体颜色。
  - 去除原有的“批量分析”、“分析”等直接操作按钮，在卡片上统一增加**复选框（Checkbox）/选择按钮**。
  - 默认分页：每页 20 条，支持自定义。

#### 步骤 1：因子选择 (Factor Selection)
- 完全复用现有的 QE 因子库列表显示和筛选功能。
- 去掉批量分析等按钮，加入复选框进行多选。

#### 步骤 2：模型选择 (Model Selection)
- 完全复用现有的模型库显示模式和内容，以卡片形式显示。
- 去掉分析按钮，提供单选/多选按钮。

#### 步骤 3：策略选择 (Strategy Selection)
- 完全复用现在的策略库显示模式。
- **特殊排版**：将策略划分为两个区块或提供明显的分组：
  1. **日频策略**
  2. **日内高频策略**（单独列出）
- 允许用户同时勾选“日频”与“日内高频”，满足组合策略需求。

#### 步骤 4：组合配置与 AI 评估 (Portfolio Assembly & Evaluation)
- **展示已选项**：清单式列出选中的因子、模型、策略（含日频与高频）。此页面为 AI 自动选择和人工配置共用。
- **“AI 评估组合”按钮**：针对生成的组合进行分析，调用 LLM 给出投资组合合理性、风险等分析报告。
- **任务分流选择**：提供明显的选项 —— **“作为独立任务执行”** 或 **“启动 QE 自动演进”**。

#### 步骤 5：任务下发设置 (Task Dispatching)

##### 分支 A：独立任务 (Independent Task)
- **定义**：单次生成 Qlib 配置并执行，不进行代码演进。
- **操作**：直接生成 qlib 配置，点击执行后通过 API 传输到 WSL 环境执行。
- **兼容性**：独立任务的所有运行状态和各种数据，将完全兼容并显示在“自动演进”功能页面中。

##### 分支 B：QE 演进任务 (QE Evolution Task)
- **保留旧功能**：保留目前从现有完成实验开始演进的入口功能（例如提供一个切换“从现有实验延续”的选项）。
- **目标确认**：要求确认实验目标。若是 AI 智能生成的，提供编辑功能；若是纯人工配置选择此项，则强制要求输入演进目标。
- **参数输入**：提供演进任务需要的 Loop 数量等信息。
- **操作**：提交后同步到 WSL 环境，开始一个新的演进任务，在自动演进页面随时查看状态。

## 3. 需补齐的系统限制与后端 API 缺口

要完美实现上述前端设计，我们需要在后端和底层补齐以下功能：

1. **AI 智能选择映射接口 (`POST /api/experiment/smart-select`)**：
   - 接收用户的自然语言需求，让 LLM 检索当前数据库中可用的因子、模型、策略，返回精确的 ID 列表供前端打勾。
2. **组合评估接口 (`POST /api/experiment/evaluate-portfolio`)**：
   - 接收选中的组件，输出专业的文字版分析报告。
3. **冷启动组装引擎 (Cold Start Workspace Builder)**：
   - 核心难点：原生 RDAgent 必须基于真实文件和 Trace。当用户选中前端的几个因子和模型时，后端必须在 WSL 内动态创建一个干净的初始目录（Task 0），将选中的代码注入进去，生成初始的 `workflow_config.yaml`，以此作为独立任务或演进任务的“基座”。
4. **演进面板兼容独立任务 (`GET /api/evolutions`)**：
   - 自动演进页面的数据结构（通常是树状的 Node/Edge）需要兼容“单节点”的独立任务。独立任务在前端展示为一个不会生长子节点的根任务，但同样具备日志、图表、回测指标查看功能。

## 4. 给您的合理化建议

1. **前端组件复用模式：**
   - **建议**：不要为选择页面重新写一套列表代码，这会导致后期维护噩梦。强烈建议在现有的 `FactorList.tsx`, `ModelList.tsx` 等组件中增加一个 `mode="selection"` 属性。在选择模式下，隐藏分析按钮，暴露出选择框，这样能 100% 保证字体、颜色、风格与库管理页面永远一致。
2. **日频与高频组合的底层执行逻辑：**
   - **建议**：Qlib 底层对日频和高频的数据回测管线差异巨大。如果前端允许同时选择日频和日内高频策略，底层 WSL 执行环境必须具备“策略融合执行器（Meta-Strategy）”的 Python 代码（即日频定仓位，高频定买卖点）。如果目前底层还不具备这种融合代码，建议系统在生成 Qlib 配置时，提供一个默认的模板桥接器，或者在 AI 评估环节提示该组合的技术挑战。
3. **保留从现有实验演进的UI融合：**
   - **建议**：在第一步进入“QE实验设计”时，提供两个大的标签页或开关：【新建组合实验（支持独立或演进）】 vs 【从历史实验继续演进】。后者直接复用以前的逻辑，弹出一个历史实验下拉框即可，不干扰复杂的选择流程。

## 5. 需要您明确/回答的细节问题

在动手写前后端代码之前，请您帮忙确认以下几个细节：

1. **独立任务底层执行方式**：对于单次执行的独立任务，我们是直接在 WSL 里拼凑一个纯净的 `qrun xxx.yaml` 命令，还是依然套用 RDAgent 的外壳（例如让 RDAgent 跑 0 个 Loop）？（强烈推荐后者，这样状态监控、日志提取能和演进任务完全共用一套代码逻辑）。
2. **代码提取逻辑**：当我们从零选择因子、模型并提交时，后端是否已经有了将特定因子/模型 ID 对应的 `.py` 源代码从数据库中提取出来，并写入到 WSL 实验目录的标准化 API 脚本？
3. **底层回测能力**：目前底层的量化引擎是否已经实际跑通了“日频+高频”结合的策略逻辑？如果底层跑不通，UI 开放选择后在实际回测环节会失败。
4. **UI 主题同步**：为确保页面风格、字体完全与自动演进页面统一，前端是否有全局统一的 Theme/CSS class 可以直接挂载？（例如 `dark-theme`, `card-evolution` 等）。
