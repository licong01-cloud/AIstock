## 第一轮：源码事实、架构边界、过度工程

已读取LocalSIM实际planning/runtime、Trading Core adapter/engine/ledger、BaseExecutionAlgo/TWAP源码及其上位设计，并与蓝图逐项对照。

| 项目 | 发现/风险 | 修订与结论 |
|---|---|---|
| 实际接口 | LocalSIM不是MiniQMT，且现行TWAP-only；不能直接选择任意策略 | §2/§3.4明确扩展由LocalSIM owner负责，不恢复V25、不改旧release；设计事实已闭合 |
| 成交语义 | StepResult/StepFill表示子成交，核心机会不等于成交 | §3.4规定adapter待执行与确认反馈；§5独立核心回放不冒充LocalSIM账户收益 |
| 费用/基线 | 原TWAP用当前bar close，FeeModel不是个人分项净佣费用合同 | §4.2保留native与matched两种对照，费用身份独立，不能从算法名推断时间/价格语义 |
| GET副作用 | 初稿未指定有状态核心由谁持久化，GET可能悄悄推进状态 | §3.5增加幂等POST evaluate，GET只读；复用claim但不把claim叫送达 |
| 数据可见时间 | 初稿只约束source available_at，未把实际收到时间纳入因果判断 | §3.2改为max(bar_end, source_available_at如有, received_at)，历史缺采集时间显式用假设 |
| 计划生命周期 | 机会状态不能兼任计划取消/完成状态；重试身份遗漏到期时钟可能冲突 | §3.1增加独立生命周期与时钟事件身份，机会边沿另去重，不因时间刷新重复弹窗 |
| 输入审计 | 仅hash且无可回读历史输入不足以重算盘中决策 | §3.6保存实际有界窗口或可回读版本引用，不留无界原始payload |
| 过度工程 | 为接口复用引入第二账本、平台或复杂通知设施的风险 | 两阶段不变；无新平台、全局registry、SSE、常驻worker；只处理目标计划 |

本轮修订已写回蓝图，随后执行第二轮因果/实验口径及全篇一致性复核。

## 第二轮：因果、评价、全文一致性

对修订后的§3～§6重新通读，并按以下失败路径检查；本轮不是运行策略测试。

| 项目 | 发现/检查 | 处理与结论 |
|---|---|---|
| 取消与迟到成交 | 决策排队后源计划可取消，延迟不能使旧意图继续成交 | §4.3明确取消/修订/决策过期即失效；§3.5每次刷新前核对来源revision，无法核实不弹新提醒 |
| 人工时钟 | D0若用信号bar close会偷用不可成交历史价；strict-after还有分钟取整等待 | §4.3增加09:31:10示例，明确下一eligible bar open和实际等待秒数，D0不是收益上界 |
| 午休边界 | 初稿“120分钟”措辞不必要且易误导 | 改成由交易日/时段判断应到bar，闭市不计行情缺失；不硬编码午休长度 |
| 未来成交量 | 完整执行bar可能被用于数量限制，但不能反送至开盘前核心 | §4.3区分事后区间成交模型与前缀信号，不宣称开盘盘口可成交；adapter不能静默换close |
| 持有期 | “固定终止日期及持有期”可能被理解为晚买后仍维持完整时长 | §3.3固定相对原计划日的horizon和终止日，实际晚买的剩余持有时间可以缩短 |
| 没有价集 | C1到价策略在NONE模式无实际定义 | §4.1明确C1不适用，B0/C2可继续；不造无限价集；保留缺失/未知人口比例 |
| 延迟与闭环 | 相同机会流的纯延迟实验和成交反馈改变后续机会的闭环实验不同 | §4.3分别报告，四份状态隔离；不以成交子集或最优延迟代表整体 |
| 研究身份 | 新分支不能隐式承接R8或active profile，源数据变化可能污染比较 | §4.4增加完整request冻结内容，研究文件显式绑定，无删股缩期或补0 |
| 双阶段一致性 | 核心可先交付，但不能将缺LocalSIM产品接入称完整交付 | §5明确三个工作面仍在同一阶段，独立发布与整体完成分开；研究无收益/未来日准入门禁 |

## DESIGN-COMPLIANCE-001 逐项结果

1. 禁止简化交付：本轮仅交付蓝图，两个消费接口均在设计范围；未把无LocalSIM接入的核心称完整产品。
2. 禁止静默错误：未知、陈旧、取消、价集缺失、不可成交分别显式表达，无数据/策略fallback。
3. 禁止改变业务逻辑：不改旧日频策略/实验/费用；LocalSIM TWAP-only仍有效，扩展由其owner更新上位合同和代码；不恢复V25。
4. 禁止私增门禁：只要求数据/身份/因果正确性，不加审批、MDE准入、sealed holdout前置或未来自然日等待；蓝图确认后再开展下一步是本次任务边界。
