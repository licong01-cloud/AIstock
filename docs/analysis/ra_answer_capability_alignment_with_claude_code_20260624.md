## 0. 范围声明

本设计稿**只谈"回答问题的能力"**,不涉及写代码能力。目标是让 AIstock 研究助理(RA)在**自主收集信息、综合判断、诚实有据**这件事上无限逼近 Claude Code 的体验。

**用户已拍板的前提**:模型差距搁置——DeepSeek V4 接 Claude 框架,回答问题的能力基本够用(仅写代码差距大),因此**本轮纯从软件架构改进**,不依赖换模型。

## 1. 核心洞察:两种循环范式

| | Claude Code(目标态) | RA(当前) |
|---|---|---|
| 循环主导权 | **模型主导**:模型自己决定调什么、调几次、何时停、何时答 | **框架主导**:语义预路由 + 框架框定的循环 |
| 质检者 | **模型自己**就是质检,无外部闸门 | **确定性闸门**(grounding guard)事后审判模型 |

**一句话**:Claude Code 是"模型主导循环 + 模型自己当质检";RA 是"框架主导循环 + 确定性闸门审判模型"。

让 RA 像 Claude Code = **把决策权从框架交还给模型**,同时**只保留两道生产必需的护栏**(审批门 + 反幻觉)。

## 2. Claude Code 循环本质(4 个特征)

```
收到问题
  └─ while(模型判断信息还不够):
        模型看着【全部工具】→ 自己选一个或几个调 → 读结果 → 决定下一步
  └─ 模型自己综合 → 直接输出
```

1. **模型看见全部工具**(不是框架先筛一个子集)
2. **选什么 / 选几个 / 调几轮全由模型定**(框架不预判)
3. **无外部闸门事后审判**(模型自己保证质量)
4. **模型自决何时停、何时答**(没有硬上限替它喊停)

RA 当前这 4 条**都被框架接管了一部分**——下面 6 条改进就是逐条把决策权交还模型。

## 3. 六条架构改进(按杠杆排序)

### 3.1 路由:钉死 → 种子建议(核心)
- **现状**:`_semantic_or_legacy_route_decision`(service.py)语义预路由,本质是"框架替模型先决定该调哪个工具"。B2/BUG-509 已放开成候选集,但**候选集仍是框架算出来的**——模型还在"框架划的圈"里选。
- **目标**:预路由从"决定调什么"彻底降级为"**可选的提示**"。seed = 建议,模型可无视、可追加任意工具。框架只负责**把全部可用工具暴露给模型**,选择权 100% 交还模型。
- **落点**:service.py 路由决策;ReAct 循环工具注入。
- **护栏**:写动作仍按审批门治理(见 §4)。

### 3.2 工具暴露:子集 seed → 全只读域可见
- **现状**:能力的 `mcp_tool_refs` 决定模型这轮"能看见/能调"哪些工具,是个被治理的子集。**国城矿业只用一两个工具的根因**=它根本没看见其他工具。
- **目标**:对话/分析场景,默认把**整个只读工具域**暴露给模型,选择交给模型;不再先 seed 一个窄子集。
- **落点**:`_agentic_function_tools` / capability mcp_tool_refs 的可见集构造。
- **护栏**:写/副作用工具仍经审批门;只读全可见。
- **验证**:可选集 == 可执行集 == 完整只读域(BUG-412 同源原则)。

### 3.3 grounding guard:风格警察 → 退回事实警察(最伤体验)
- **现状**:grounding guard 兼管"必须综合不许罗列"(风格)→ **误杀合法的事实清单**(QE "前 10 loop 收益+模型" 查询被拦 `Insufficient evidence: business reply synthesis did not pass grounding guard`,但数据完好)。
- **根因**:guard 用"判断型综合"的尺子量"事实清单型查询",分类错误(假阴性)。
- **目标**:guard **只保留事实校验**——有据 / 不编造 / 标注未验证风险(反幻觉,**绝不削弱**)。**风格(综合 vs 罗列)交还模型 + prompt**:判断型问题逼综合靠 prompt 引导,事实/排名型问题允许结构化清单为合法形态。guard 从"事后审判"退回"兜底安全网"。
- **落点**:react_grounding.py 的 `_is_business_synthesis_summary` / `multi_source_synthesis_missing` 等规则。
- **关键边界**:不放水**真正的**模板堆砌;事实型清单**仍须**每行带来源/日期 + 对 `not_verified` 数据强制风险标注。

### 3.4 停止条件:硬上限/强制迭代 → 模型自决 + 兜底
- **现状**:`max_tool_iterations` 硬上限(调几个就停)+ guard 强制迭代(没过就逼着再调)。两个外部信号替模型决定"够没够"。
- **目标**:上限放宽到只作**防失控兜底**(防死循环);正常情况让模型自己说"够了"。强制迭代只在"明显没取证就想答"时兜底,不替模型判断充分性。
- **落点**:react_grounding.py 循环控制 + runtime config `max_tool_iterations`。

### 3.5 mode 分层:多层打架 → 目标对齐
- **现状**:root + mode.dialogue/analysis/planning/preflight 多层提示词,目标可能冲突——**mode.analysis 允许"先问一个澄清" vs grounding 要取证**,导致多维问题被打断(国城矿业第一次)。
- **目标**:让各 mode 目标对齐到同一件事(自主取证 + 综合),消除"一层允许、另一层禁止"的内耗;**澄清收窄到真歧义**(实体不明 / 意图自相矛盾才问;多个明确维度 = 全部都做,不得用澄清代替取证;澄清也须中文)。
- **落点**:`prompt_packs/research_assistant/main/nodes/mode.*.md`(YAML 权威,reload 生效)。

### 3.6 错误哲学:全域 fail-closed → 分级
- **现状**:fail-closed 是全局原则——可疑就拦、返回结构化错误。事实型查询也被一刀切拦死(QE 那次拿不到任何数据)。
- **目标**:fail-closed **只守写动作 + 反幻觉红线**;只读查询即使部分证据不足,也应**给出已有的 + 标注缺口**(降级),而不是整体拒答。
- **落点**:react_grounding.py guard 决策 + service.py 错误返回路径。
- **护栏**:写动作 / 反幻觉仍 fail-closed,不变。

## 4. 绝不动的两道护栏(RA 该与 Claude Code 不同之处)

这两条是生产场景必需,**任何改进都不许削弱**:

1. **审批门**:写 / 提交 / 训练 / 晋升 / 生产变更必须用户对话内显式确认令牌;四重校验;side_effect 分级;只读才自动执行。(理由:RA 半自主操作生产交易系统,等同我改代码也要用户 review。)
2. **反幻觉事实底线**:每个事实 inline 来源 + 日期;数字有据;禁占位;禁编造;未验证数据强制标风险。(理由:量化场景编一个收益数字可能让用户真亏钱。我也守这条,只是我自律、RA 靠 guard 他律。)

**终局不是 RA == Claude Code,而是 RA 回答体验无限逼近 Claude Code,同时保留生产必需的审批门 + 反幻觉闸门。**

## 6. 验收(纲领级,防回退到框架主导/闸门误杀)

1. **自主多工具**:个股全方位问题 → 模型自选并调齐多个只读工具(行情/历史≥60日/资金流/基本面/技术/联网),非框架钉死、非只调一两个。
2. **事实型不误杀**:QE "前 10 loop 收益+模型" 类查询 → 正常返回结构化清单 + 每行来源/日期 + not_verified 风险标注,**不再被 guard 拦死**。
3. **判断型仍综合**:个股"怎么样"类 → 先 bottom-line 综合判断,不退回模板罗列。
4. **多维不打断**:清晰多维问题 → 直接全做,不反问澄清;真歧义才问且中文。
5. **只读降级不拒答**:部分证据不足 → 给已有 + 标缺口,不整体返回错误。
6. **未来不预测**:驱动/情景/风险 + 免责,无方向预测(B2 forecasting 纪律不回退)。
7. **护栏不动**:写动作仍走审批门;反幻觉(有据/不编造/标风险)对所有答案仍强制。
