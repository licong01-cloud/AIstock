# LocalSIM 停牌估值消费端与原任务接续修复合同

关联 BUG-1936 / Issue #6178，接续 BUG-1929 及 BUG-1934。范围限 LocalSIM；不修改共享选股算法、策略包、QE、HMM、行情数据、账户资金或账本算法。

## 真实触发

用户重启后 BUG-1929 已加载。两个原 recover 在原全局门禁自然放行时正式受理；TCN 2026-05-11、LSTM 2026-01-21 实际重建计划后，均被 scheduler 的 `LOCALSIM_SUSPENDED_DAILY_FACT_INVALID` 拒绝。生产者已经生成新停牌 mark，消费端却仍仅接受旧 `daily_trading_context`。

TCN 301139.SZ 的 C=05-08 真实参考价为 18.45；LSTM 603616.SH 的 C=01-20 真实参考价为 6.23。两日七类经济表均为零，回滚内存批次分别为 31/19 个句柄。LSTM 原 18 个句柄的核销收据已经存在。原生命周期将本次失败保持为 `FAILED_RETRYABLE`，不能通过人工制造 `FAILED_TERMINAL` 接续。

LSTM 已成功的 01-20 整行、原计划及证据身份、七类经济表记录及摘要均保持不变；类型化行、Asia/Shanghai 会话、排序字典行的复核收据为 `X:/AIstock_temp/LOCALSIM/workflow/BUG-1929-prefix-typed-row-readback-20261016-r1.json`。

## 必须保持的合同

1. 消费端继续使用 `LocalSimMarketMarkV1` 及现有纯证据校验函数，不复制参考价查找算法。新停牌来源必须与本日冻结 tradability 的唯一权威载体完全相符；验证 D 日停牌、C 日截止、股票、价格、来源、时点及摘要。历史来源以外、双权威、篡改、陈旧或缺失证据明确拒绝；原旧 V1/V2 路径保持。
2. 停牌历史参考价是独立估值来源，禁止写作 `pre_close`。普通可交易股真缺价、S/R 事实冲突及无权威参考价继续拒绝。历史终结必须复用同计划的原 mark，不能重估成功前缀。
3. 回滚批次核销仅扩展到已经证实的 `LOCAL_SIM_MARK_VALIDATION_FAILED / LOCALSIM_SUSPENDED_DAILY_FACT_INVALID`；完整计划及意图身份、七表零经济事实、broker 未调用、未暂存提交、无有效重试租约和旧进程时间证明仍全部成立。
4. 再次核销时保留前次完整收据及原始 payload，新增 `predecessor_retirement_sha256`。逐层验证摘要、稳定运行身份、提交时间先后及句柄不重复。不得覆盖或丢失原 18 个句柄的证据。
5. 同一个正式 recover 仅为上述已知估值失败、可核销旧进程批次和原生全日停牌证据完整的 `FAILED_RETRYABLE` 增加受理范围。其他失败类型仍遵守原状态合同；RUNNING、未知状态和活跃进程批次均拒绝。保留 job/account/run 锁、经济锁、版本及摘要 CAS、锁内重查、事务回滚与回读。更新必须匹配实际检查过的原状态。
6. 调度器在正式恢复前明确返回 `LOCALSIM_REPLAY_RECOVERY_REQUIRED`，保留该已知失败批次，避免重启后盲目续用旧内存句柄并覆盖原失败证据。不自行调用调度 tick，不重置任务、日期、终态或断点，不新建替代回放。用户重启后重取正式证明；后续由原生命周期推进连续日、冻结全程、原生 catch-up 及全局安全边界上的正式 LocalSIM 激活。
