# LocalSIM 原回放受控恢复合同（BUG-1926）

## 问题与边界

修复已补齐的数据或依赖后，原回放仍为 FAILED_TERMINAL，不能靠手改状态、新建回放或复用旧 C 日资格投影恢复。本次增加正式检查及恢复命令，保留原 job/run、成功前缀、账户、绑定、资金及交易账本。该命令只恢复失败日的调度资格，不直接执行交易。生产执行仍遵守本窗口授权边界。

依据：共享内核接入设计、PR #6105 的停牌 D / 风险行业参考价 C 合同，以及日行情冻结设计。属于既有 BUG 的 T3 恢复合同修复；不增加估值政策、不修改共享算法或数据模块。

## 恢复规则

1. 只允许未激活到实时盘的历史终态、精确版本及失败日期；原 source/calendar/day-engine/release/binding/manifest 必须一致。拒绝成功、取消、已激活、身份不符和未知故障。
2. 从原生订单、事件、成交、现金流水、持仓快照、日快照和 paper run 读取真实事实，并检查执行状态、经济收据、outbox、提交句柄和重试租约。缺失 broker_called 字段本身不是无副作用证明。
3. 仅处理原生缺价故障；用原生 DB_HISTORICAL 行情入口重新检查失败标的，不推算或补值。合法停牌但无权威 pre_close 保持 BLOCKED。上一日 09:33 的报价不是收盘价，也不是 D 日 pre_close。
4. GET 检查不写库。POST 在同一事务中锁定原 job/run、取得原生经济锁、重新检查事实及行情，通过摘要和版本校验后写入恢复谱系，CAS 转为 FAILED_RETRYABLE。任何失败全部回滚；并发/重复旧命令不得再次生效。
5. 失败日保留旧 evidence/plan 不可变记录；恢复谱系要求下一次原生日引擎重建计划。已完成日期不可重建。共享链重做 D 日资格过滤，不复用旧投影。已有合法 LocalSIM 冻结完整评分可由原生服务重新准备并进入共享内核；无此完整冻结产物则重新独立推理，禁止从业务缓存补齐。
6. 计划重建前再次核对零经济事实及恢复谱系。计划发布后由现有订单、幂等、经济提交和 outbox 路径推进，不改变交易语义。崩溃前未提交的计划不得作为已恢复结果。

## 明确未解决的业务合同

LSTM 603616.SH / 2026-01-21 为合法停牌且权威 pre_close 无有效值。现有估值合同仍需要该值。当前没有批准的停牌估值替代政策，必须保持 BLOCKED；本修复不将历史成交价、成本价或上一日盘中价冒充权威估值。该缺口归 LocalSIM 估值 owner，不再要求数据窗口制造数值，也不要求荐股业务层补值。

## 审核与实测

1. 第一轮修复原生日证据日期字段引用，并区分恢复前未释放租约和重建时本次调度拥有的租约。
2. 第二轮修复不可变证据数组的 JSON 还原、跳过推理时的原生 PIT 日期解析及原生 v2/旧哈希探测；完整评分不重算，原生身份不匹配仍拒绝重新生成。
3. 第三轮补齐事务回读、经济锁互斥和重复 CAS 拒绝；没有因 broker_called=false 而忽略 LSTM 的 18 个提交句柄。

定向相关矩阵 61 项通过；现有 DEV 合同 3 项通过，增加事务回读后再次验证唯一受影响 DEV 用例通过。Ruff、编译及 diff 检查通过。跨模块 simulation_core_l2 由最终源码 CI 验证；nightly 深验按工作流登记。
