## Boundary Model

- R7 should remove expensive foreground work from interactive HTTP paths where there is already a concrete design, especially ST PIT rebuild. The accepted design says strict consumers should read readiness and fail fast with job hints, while operator APIs enqueue/reuse background jobs instead of rebuilding inline.
- R8 should consolidate remaining sync DB/filesystem/subprocess work behind explicit executor or worker boundaries, then gradually replace psycopg2-style route/service calls with async repositories or durable job records where latency can exceed a short request budget.
- Good existing patterns: `BacktestExecutor` offloads `compose_experiment_in_memory()` through `run_in_executor`; LLM model listing uses `httpx.AsyncClient`; many factor analysis endpoints use `asyncio.to_thread()` for CPU/sync services.

## Recommended Migration Order

1. R7 ST PIT job service first: it has an approved design, clear acceptance criteria, and direct links to QE/Paper/Selection safety.
2. Wrap or refactor multi-alpha composition next, because it is the most visible async route that bypasses the existing `BacktestExecutor` offload model.
3. Standardize dispatch-service DB access behind one async-safe repository/executor boundary before adding more remote-node polling or batch operations.
4. Convert result-sync and webhook processing to durable jobs where operations can exceed a short request budget.
5. Add a lightweight audit check for new `async def` functions containing direct `get_conn()`, `requests.`, `subprocess`, or `time.sleep` without `to_thread`/`run_in_executor`.
